## 0. 한 장 요약

- **답변 API 는 끝났다.** `/ask` 9단계 전부 · `/walk` 전부 구현·배포. 코퍼스 8,990문서 / 22문항 lap14 = cited 17 · grounded 13.
- **수집은 닫혔다.** 문서형 시드 23 중 16 수집, 남은 7 은 robots·WAF·SPA·문서 부재로 우리 손 밖 (`data-sources.md` §0).
- **운영 뼈대만 남았다** — #65(코퍼스 서버 이관) · #66(개정 감지) · #67(고시공고). 서버 물리 접근이 필요해 **다른 날·다른 자리**.
- **다음은 "툴로서의 완성"이다.** #80 에서 이 파트는 에이전트가 아니라 **능력(capability)** 이고, Life·Walk 둘 다 v1 실행 대상.
  통합 첫날 실제로 도는 능력은 이 둘뿐이다 (§2). 그래서 순서는 **A 툴 완성 → B 어댑터 준비 → Card 1** 이고 나머지 트랙은 틈에.
- **범주 확장(`food` 등)은 경계 신호가 먼저다** (§3 F). 경계는 주제가 아니라 **근거의 종류**로 긋는다 (§2).

## 2. 오케스트레이션 안에서 이 파트의 자리

계약·상태·라우팅은 `orchestration-contracts.md` · `orchestration-routing.md`(#80) 가 원본이다. 여기서는 **이 파트가 그 틀에
꽂히려면 무엇을 내야 하는가**만 적는다.

```
/assistant/query → LangGraph
   라우터(분류기) → RoutePlan{requests[], handoffs[], clarify}
   → LifeCapabilityAdapter.run(LifePayload)  ─in-process→ daengs_life.app.services.ask.ask()
     WalkCapabilityAdapter.run(WalkPayload)  ─in-process→ daengs_life.app.services.walk.walk()
   → CapabilityResult{OK | ABSTAINED | REFUSED | PENDING | ERROR | TIMEOUT}
   → 결정적 집계 → AssistantResponse
```

### 경계 — 주제가 아니라 **근거의 종류**로 긋는다

"생활"은 주제로는 끝이 없다. 이 파트의 실제 경계는 처음부터 하나였다: **출처를 인용할 수 있는 답만 한다** (KPI · `/ask` 의 404 ·
RAG-008 ③ 이 `care`·`emergency` 를 뺀 이유).

| Life 가 답한다 | 근거의 종류 |
| --- | --- |
| 규정 · 제도 · 절차 · 조건 · 요금 · 기한 | 법령 · 조례 · 고시 · 약관 · 기관 공식 안내 (`trust_level`: `law` > `official` > `guideline`) |
| 지금/오늘의 조건 판정 | 공공 API 직조회 — `/walk`, (앞으로) 분실 조회 |

| Life 가 답하지 않는다 | 이유 | 넘길 곳 (`handoffs[].target` 식별자) |
| --- | --- | --- |
| **이 개의 몸**에 대한 판단 — 증상 · 진단 · 용량 · 응급 | 문서가 아니라 판단 (RAG-008 ③) | `medical` / `emergency` |
| **이 개의 행동**을 바꾸는 계획 — 짖음 · 배변 · 입질 교정 | 〃 | `training` |
| **어디** — 병원 · 카페 · 숙소 위치 | 장소 데이터는 place 소유 (D-026) | `place` |
| 근거 문서가 코퍼스에 없는 것 | — | 기권 `no_evidence` (넘길 곳 없음) |

이렇게 잡으면 ① 경계가 코드로 강제되고(코퍼스에 있는 것 = 경계) ② 골든셋 `expect: abstain` · `expect: handoff` 로 **테스트가 되며**
③ Life 를 라우터의 **기본 능력**으로 둘 수 있다 — 실패 방식이 정직(근거 없으면 기권)해서다. 상대 파트가 아직 안 떠 있어도
식별자는 지금 정하고, 오케스트레이터가 "준비 중"으로 렌더한다.

### 이 파트가 내야 할 신호 — 현재 / 목표

| 신호 | Life 현재 | Life 목표 | Walk 현재 | Walk 목표 |
| --- | --- | --- | --- | --- |
| OK | 200 | 200 + 축소된 응답 (O-9) | 200 | 200 |
| ABSTAINED | 근거 0건 → 404 만 | + 약한 근거 기권 (`no_evidence`) | `unknown` → 503 | ABSTAINED 로 확정 (계약 표의 "후보") |
| REFUSED / HANDOFF | **없음** — 산문 물러섬이 OK 로 통과 | `medical` · `emergency` · `training` · `place` 감지 | — | — |
| ERROR / TIMEOUT | 502 / 504 | 그대로 | 503(예산 초과) | 그대로 |
| 컨텍스트 입력 | `question` 하나 | + 지역 · 반려견(견종·나이·등록) | `lat` `lon` | + 프로필 기본 위치 (CLARIFY 회피) |

## 4. 순서와 의존

```
A1 증분 임베딩 ──┬─→ A7 insurance 분리 ──→ F1 food ──→ F4 주거
                 └─→ D3 파서 경계

A2 지역 필터 ──┐
A3 경계 신호 ──┼─→ B1 페이로드 ──→ B2 어댑터 ──→ B3 접점 테스트 ──→ [Card 1 — 팀 카드, #80]
A4 축소 ───────┘         ↑
A5 특보 매핑 · A6 Walk 매핑 ─┘                               B4 반려견 컨텍스트 (#64 뒤)

C1 → C2 · C3 · C5   (병렬, 서버가 있는 날)        C4 는 언제든
D · E 는 틈에.  F0 정찰은 A3 와 병렬.  F2 분실 툴은 독립.  F3 장례 문항은 언제든.
```

- **A1 을 소스 카드(A7 · F1 · D3) 앞에 두는 이유** — 그 셋이 각각 55분을 다시 내기 때문.
- **A3 이 F 전체의 전제인 이유** — `food` 를 넣는 순간 경계 질문("먹었어요")이 폭증한다. 신호 없이 넣으면 사료 조문으로 답한다.
- **B 의 우선도가 처음 생각보다 높은 이유** — 통합 시점에 실제로 도는 능력이 Life·Walk 뿐이라 Card 1 의 첫 데모가 이 파트로 돌아온다 (§1).
- Iteration 은 3~4일 (`collaboration.md`). 위 행 하나 = 카드 하나가 원칙이고, A3+A4 · A6+B1 처럼 묶어도 되는 것은 표에 적었다.

## 6. 열린 결정 (사람 몫)

- **`insurance` 독립 category** — 2026-08-30 "나중에 뺀다"로 방향만. 시점은 A1 뒤 (A7).
- **지역 필터의 형태** — RAG-033 ⑥ 의 셋(org 사전필터 / BM25 신호 / 되묻기) 중 무엇을 기본으로 할지. A2 카드가 실측으로 제안한다.
- **핸드오프 식별자 표** — `medical` `emergency` `training` `place` 는 이 문서의 제안. 통합 때 파트별 "답한다 / 답하지 않는다 / 넘긴다" 세 줄로 확정.
- **라우터 모델** — v1은 `gemini-3.1-flash-lite`로 확정(D-041, 2026-09-01 정정 — 최초
  Card 2A/production 구현은 사람의 모델 선정 기억 착오로 `gemini-3.5-flash-lite`를 썼다).
  Card 2A/v4는 모델 비교가 아니라 동결된 기준에 대한 수용성 검증이다. `gemini-3.1-flash-lite`는
  Training **생성**에도 쓰이지만(별도 프롬프트·런타임 경로), 라우터로서의 채택 근거는
  `docs/orchestration-router-benchmark.md`의 v4 수용 벤치마크다.
