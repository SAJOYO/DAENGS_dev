# 이동 재료와 활동 서술

2026-09-14, DEV #520. 형상 판별과 내부 이동 분석을 확장한다.

**행동 생성·최종 입력은 #527의 [행동 핀 경계](diary-action-boundary.md)를 적용한다.**
핀 없는 이동 서술과 원문을 포함한 제목 입력은 폐기했다. 아래 v4/v5 입력·실험 절은 과거 기록이다.

## 구현 단위

- GPS만으로 방향 변화 후보의 범위를 확정하고 굽이·국소 회전·관측 가능한 방향 변경을 구별한다.
- 최근 과거 동선과의 역순 대응을 별도 관계로 보존한다. 현재 진행 기준으로 좌우를 계산한다.
- 상대 속도는 원래 연속 구간에서 0.5배 미만·1.5배 초과·10초 이상으로 판정한다.
- 내부 분석을 카드 범위로 자른다. 행동 기록은 이동 분석을 바꾸지 않는다. 최종 소비는 행동 핀 시각으로 한정한다.
- 실제 행동 요청은 행동 핀과 그 시각의 이동 맥락 최대 1개다. 시간·각도·거리·정책 수치는 내부에 둔다.
- 행동 프롬프트는 기록된 행동을 중심으로 쓴다. 전체 동선의 순서를 서술하지 않는다.

기존 공간 작성·본문 코드 조립·전체 맥락 제목·발행 경로를 사용한다. 과거 GEO 실험과 저장된 기록의 읽기 계약은 유지한다.

## 확인 범위

굽이/코너, S자/직선, 되짚기/평행 동선, 카드 부분 범위, 핀 변경, 실제 요청 정규화와 저장 재조회를 대상으로 한다. 새 외부 API나 모델 호출을 자동으로 추가하지 않는다.

## 책임과 순서

`route/movement_geometry.py`는 GPS와 정책만 받는다. 기록핀이나 카드 ID는 분석에 관여하지 않는다.
`route/movement.py`는 그 결과와 원래 연속 속도 에피소드를 같은 원본 시간축에 둔다.
`slots/movement.py`는 기존 카드의 중간점 설명 범위로 적용 구간을 자른다.
전환은 그 범위에 포함되는 사건으로 연결하며, 이전의 ±20초·15m 추가 제한을 사용하지 않는다.
`board/action_context.py`는 핀 시각의 phase에서 형상·되짚기·속도를 맥락 하나로 합친다.
기존 `activity_materials.py`의 카드 전체 흐름 조립기는 제거했다. 내부 사건 순서는 보존하지만
LLM 입력으로 전체 여정을 넘기지 않는다.

행동은 이동 분석 후 연결한다. 행동 내용 변경은 GPS 분석 ID를 바꾸지 않는다.
핀 시각이나 카드 구성이 바뀌면 카드별 투영과 작성 입력은 달라질 수 있다.

## 형상 조건 — 초기 정책, 산책 표준이 아님

| 조건 | 현재 값과 의미 |
| --- | --- |
| 방향을 계산할 관측 거리 | `max(30m, 보고 정확도 중앙값 × 4)`. 보간점 대신 원본 관측을 선택 |
| 변화 후보 | 인접 진행 방향 차이 8° 이상. 안정된 방향 구간·좌우 반전·135° 이상 국소 변화에서 후보 분리 |
| 최소 변화 | 후보의 부호 있는 누적 변화 20° 이상 |
| 굽이 | 같은 방향의 변화가 3곳 이상, 누적 30° 이상, 최대 개별 변화/누적 변화 ≤0.6, 직선 이탈이 위치 오차보다 큼 |
| 국소 회전 | 분산된 굽이가 아니며 꼭짓점 앞뒤 원본 관측이 각각 2개 이상 있고 보고 정확도가 있음 |
| 큰 꺾임·반전 | 큰 꺾임 >135°. 반전은 전후 방향 차이 ≥160°. 누적 회전량과 최종 방향 차이를 구별 |
| 세부 형태 부족 | 관측된 좌우 방향 변경만 남김. 불명확한 것을 직진으로 채우지 않음 |
| 직선 | 기존 RDP와 직선 이탈 조건을 사용. 굽이와 겹친 작은 직선 조각은 제외 |
| 체류와 느린 전진 | 기존 영역·시간·진행량 조건에 시작/끝 순이동 ≤min(영역 지름/2, 정확도×2)를 함께 요구 |
| 되짚기 | 15m 관측 간격, 최근 500m 범위의 과거 선분과 비교. 공간 근접·반대 방향 30° 이내·과거 경로 위치의 연속 감소·40m 이상 역순 대응 |
| 평행 경로 | 횡방향 이탈은 min(기존 10m 통로, max(1m, 정확도/2)) 이내. 서로 다른 과거 방문이 비슷하게 대응되면 보류 |

위 수치는 코드에 있는 조절 가능한 초기 휴리스틱이다. 내비게이션의 도로 형상 수치를
GPS 산책의 검증된 정답으로 옮긴 것이 아니다. 후보 크기의 1/3에 60%가 집중되는 제안 대신,
관측 거리를 먼저 고정하고 최대 개별 변화 비율로 분산을 판정하는 간이 구현을 택했다.
짧은 곡선·희박한 관측·가까운 평행 길에서는 세부 의미가 누락될 수 있다. 지도 시설·도로명·의도는 추론하지 않는다.

참고한 판정 방식: [Valhalla 각도 분류](https://github.com/valhalla/valhalla/blob/master/src/baldr/turn.cc),
[OSRM 곡선 판별](https://github.com/Project-OSRM/osrm-backend/blob/master/src/extractor/intersection/coordinate_extractor.cpp#L585).
OSRM 함수는 도로 대표 방향을 구하는 과정의 판별이다. 회전교차로·차선 폭 조건은 차용하지 않았다.

## 과거 작성 입력 v4/v5 — 현재 v6으로 대체

```json
{
  "movement": {"materials": [{
    "id": "m1",
    "meaning": "앞서 지나온 구간을 역순으로 따라가며 오른쪽으로 완만하게 휘어 이동",
    "extent": "원래 이동 전체",
    "changes": [{
      "id": "m2",
      "scope": "이 이동의 끝부분",
      "meaning": "위 이동을 이번 산책의 기준보다 상대적으로 느리게 이어감"
    }]
  }]}
}
```

예시는 가정이다. 전체 이동을 다루는 카드와 끝부분만 다루는 카드는 다른 scope를 받는다.
시각·지속시간·좌표·각도·속도 수치·정책·원본 ID는 모델에 보내지 않는다. '끝부분'이라는
관계는 남기지만 '끝부분에만'이라고 나머지 구간의 부재까지 주장하지 않는다.

별칭 하나는 서버에서 여러 구간별 근거로 복원된다. 흐름만 인용하면 속도 근거를 사용했다고
처리하지 않는다. 속도 변화 ID를 인용해야 해당 속도 근거가 복원된다. 중복 복원은 제거한다.
원 관측 전체가 인용 근거로 덮이는 경우에만 기존 관측 본문의 중복 처리를 허용한다.
이는 인용 연결 검사이며 문장의 의미 정확성을 자동으로 증명하지는 않는다.

활동 프롬프트는 보호자가 읽는 담백한 과거형을 먼저 요구하고, 적용 범위·순서·주체 보존을
공통 원칙으로 둔다. 분석 조건 숫자나 케이스별 문장 사전을 프롬프트에 추가하지 않는다.
작성 정책 v6·입력 v5로 기존 작성 캐시와 구별한다. v4와 그 이전 저장본은 당시 원문 그대로 읽는다.
입력 v5는 공원 고유명·종류·거리 숫자를 제외하고 가까운 공원의 존재만 전달한다.

## 최초 구현의 오프라인 검증과 산출물 — 과거 기록

직접 영향받는 10개 파일을 선별했다. 새 형상·재료, 활동, 카드 작성, LLM 정규화, 저장 경계,
과거 GEO 표본, 미리보기 API, 공간 결합, 관측 본문, 도메인 경계다. 전체 저장소 스위트는 실행하지 않는다.
실제 Gemini·공공 API·운영 DB 호출은 없다. 작성 연결 검사는 고정 대역을 사용한다.
실기기 GPS 정확도와 새 프롬프트의 실제 문장 품질은 이번 검사로 입증하지 않는다.

최종 실행: **134개 통과(15.18초)**. 변경 Python 12개 파일 Ruff check·format 확인.
기존 v3 활동 저장본과 v1 고정 표본을 현재 리더로 읽었다. 전체 저장소 테스트나 배포는 하지 않았다.

```powershell
# backend/에서
uv run --no-sync pytest -q tests/walk/diary/test_diary_movement_materials.py tests/walk/diary/test_diary_activity.py tests/walk/diary/test_diary_card_writing.py tests/walk/diary/test_diary_llm.py tests/walk/diary/test_diary_writing_boundaries.py tests/walk/diary/test_diary_route_patterns.py tests/walk/diary/test_diary_slots_api.py tests/walk/diary/test_diary_space_integration.py tests/walk/diary/test_diary_observation_content.py tests/walk/diary/test_diary_domain_package.py --tb=short
uv run --no-sync python -X utf8 tools/replay_diary_activity.py --source evals/diary_route_scenario/public-02 --output <새 결과 폴더>
```

최종 재생은 8장면·활동 8개(이동+행동 1, 이동만 7)·전체 맥락 제목 배치 1개이며 저장 재조회가 일치했다.
양재 입력에는 서로 다른 직선 구간이 여전히 여러 개 남는다. 동일 원본 흐름의 반복 분할은 합쳤지만,
다른 원본 구간을 이름만 같다는 이유로 합치지 않았다. 실제 문장에서 반복이 얼마나 줄어드는지는
새 Gemini 호출을 한 결과로 확인해야 한다. 굽이·좌우 반전 검증은 별도의 대조 경로에서 수행했다.

[최종 오프라인 입력](../../backend/evals/diary_route_scenario/movement-materials-03/preview.html)은
저장된 공공자료와 가상 GPS를 현재 작성 경로로 재생한다. 본문은 명시적인 고정 응답이며,
검토 대상은 각 카드의 실제 활동 요청이다. 중간 01·02 재생은 정책 수정 중의 결과로 최종 결과와 구별한다.

## 후속 실제 서술 확인 · 2026-09-14 — 수정 전 실패 기록

공원 입력을 일반 배경으로 바꾼 뒤 실제 Gemini를 한 번 호출했다. 공간 8개·활동 8개는

연결 성공을 서술 품질 완료로 판단하지 않는다. [실제 출력과 대조 검토](../../backend/evals/diary_route_scenario/movement-gemini-01/REVIEW.md)를 참고한다.
공원 정규화 변경의 경계 테스트는 별도로 47개 통과했고 실제 결과의 저장 재조회도 일치했다.
