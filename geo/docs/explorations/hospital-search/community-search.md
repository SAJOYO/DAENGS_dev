# 커뮤니티 검색 — 주인의 문장으로, 지도가 아니라 커뮤니티를

> **결정 #63 으로 기각.** 원천이 없다 — 근거 인덱스([evidence-index](evidence-index.md))가
> 기록한 대로 검색 API 이용조건이 파생물 저장을 막는 방향이고, 그 조건이 풀린다는 근거가 없다.
> 구현(`app/enrich/`)과 응답의 `evidence[]` 는 제거했다. 이 문서는 같은 질문을 다시 안 하려고 남긴다.

**발상 (사용자)**: 프로필이 쌓여 있으니 그걸로 **검색 쿼리를 재작성**해서 포털 검색을 돌리면, 리뷰까지 안 가도 병원이 스스로 노출한 소개 정보나 남들 경험담에서 걸리는 게 있지 않을까.

## 실험 (research/2026-08-19-query-rewrite-experiment.md)

| 쿼리 스타일 | 걸리는 것 |
|---|---|
| 딱딱함 (`강남역 동물병원 정형외과`) | 홈페이지 메인, 디렉토리, 뉴스. 특화 없는 동네 병원 못 잡음 |
| 주인 말투 (`강아지 뒷다리 절뚝거려요 강남 어디가 좋아요`) | 병원이 쓴 **FAQ·칼럼·센터 소개 페이지** ("눈이 하얗게 변했다면…" → 안과센터), 스니펫에 세부 전공 목록 |

이름에 "안과" 없어도 안과 표방이 드러남. 네이버에선 이런 쿼리가 **지식iN·카페·블로그**로 감 — "강남 슬개골 어디서 하셨어요?" 류.

## 도구는 지도 API가 아니라 **네이버 검색 API**

네이버 개발자센터 검색 API: 블로그·카페글·지식iN·웹문서·뉴스 코퍼스별. 무료, 앱당 **일 25,000회**, `display`≤100. 응답 = 제목·링크·`description` 스니펫·날짜. 공식 API, 크롤링 아님. 스니펫 장기 저장은 약관 확인.

## 루프

```
프로필 + 발화
 → LLM: 주인 말투 쿼리 2~3개
 → 네이버 검색 API (카페글/블로그/지식iN) 스니펫 30~100
 → 스니펫에서 병원명 추출 → 우리 DB(반경 안 병원 목록)와 매칭
     · 미매칭은 버림  = 노이즈 필터 + 위치 재확보 (검색은 위치가 느슨함)
 → 매칭 병원에 evidence 부착: "카페글 3건에서 슬개골 수술 언급"
 → search() 결과 부스트 + 카드에 근거 표시, 원문은 링크
```

**거리는 우리가 계산, 근거는 검색이, 판단은 사용자.**

## 역할·한계
- **필터 아님. 부스트 + 표시.** 근거 없는 병원도 결과에 남는다
- 병원명 추출이 난이도. 반경 안 DB 병원명 리스트를 LLM에 주고 "스니펫에 언급된 것만 고르라"로 환각 억제
- 증상 문진성 콘텐츠도 딸려옴 → 관할 밖. 병원명 추출에만 쓰고 표시 안 함
- 카카오 카테고리 보강과 역할 다름. 병행
