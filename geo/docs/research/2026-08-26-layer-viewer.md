# 복구한 맥락을 사람이 지도에서 읽을 수 있는가

2026-08-26 실험. 재현:

```bash
uv run python -m scripts.spikes.territory_paint.persona_year --cache osm.json --json personas.json
uv run python -m scripts.spikes.territory_paint.layer_scenes --personas personas.json \
    --cache-sheets sheets.pkl --out layer-scenes.json
uv run python -m scripts.spikes.territory_paint.basemap --walks bbox.json --out layer-basemap.json
```

코드는 `scripts/spikes/territory_paint/layer_scenes.py`. 갈래는
[territory-paint](../explorations/walk/territory-paint.md).

## 앞 실험과 무엇이 다른가

[셀로판 회수 실험](2026-08-26-cellophane-recovery.md)이 답한 것은 **정보적으로 복구 가능한가**
였고 답은 숫자였다(코사인 −0.999, ε 0.0341). 여기서 묻는 것은 다른 질문이다.

> 그렇게 복구한 정보를 **사람이 지도에서 읽을 수 있는가.**

판정하는 것도 다르다. 앞은 평가기가, 여기는 **눈**이 한다.

## 고정 시나리오인 이유

미리 겹쳐 둔 조합만 실을 거면서 UI 를 임의 태그 조합처럼 만들면 **실제보다 되는 것처럼
보인다.** 가짜 공급자가 설계의 모든 질문에 답해서 데이터의 한계가 안 보였던 결정 #51 의
UI 판이다. 그래서 13 개 시나리오를 `layer_scenes.SCENARIOS` 에 못 박고 뷰어는 그
목록만 보여준다. 문턱도 슬라이더가 아니라 **두 단계 토글**(`전부` / `심만`)인 것이 같은 이유다.

임의 조합 질의는 DB·API 로 갈 때 한다.

## 무엇을 확인했나

**측정이 페이지 안에 있다.** 뷰어에 자가 점검 패널이 있어 아래 숫자를 페이지가 스스로 다시
잰다 — 열면 한 번 자동으로 돌고, 버튼으로 다시 돌릴 수 있다. 렌더러가 바뀌면 값도 같이
바뀌므로 결론과 증거가 갈라지지 않는다.

두 판 비교는 **픽셀 단위 평균 절대차(MAD)** 다. 처음엔 캔버스 밝기 합을 지문으로 썼는데
그건 틀린 자다 — 같은 총 밝기를 갖는 전혀 다른 그림이 얼마든지 있고, 실제로 이 실험의
차이 모드에서 그 함정을 밟았다(아래 §알게 된 것). MAD 는 화면 공간에서 직접 잰다.

아래는 1280×900 에서 잰 값이다.

### 1. 전체 장면에서 F1 과 F2 는 구별되지 않는다

같은 집·같은 두 경로·같은 연간 횟수, 계절 배정만 반대인 두 사람.

```
F1|F2 전체    픽셀 평균 절대차 0.06 / 255
```

**픽셀까지 사실상 같은 그림이다.** 앞 실험의 "연간 누적 거리 0.0158(ε의 0.5배)" 이 화면에서
이렇게 보인다 — **누적만 저장했다면 여기서 끝이다.**

### 2. 계절 버튼 하나로 갈라진다

```
F1|F2 여름    3.62      ← 전체(0.06)의 60 배
F1|F2 겨울    3.62
```

버튼 하나로 두 판의 픽셀 차이가 60 배가 된다.

### 3. 차이 모드에서 부호가 반대로 칠해진다

발산 램프(따뜻함 = 기준 장면 우세, 차가움 = 빼는 장면 우세)로 `여름 − 겨울` 을 그리면:

| | 따뜻함 비율 |
|---|---:|
| F1 | **0.646** |
| F2 | **0.365** |

코사인 −0.999 가 화면에서 **색 반전**으로 나타난다. 숫자를 안 봐도 읽힌다.

### 4. 대조군 A 는 어느 장면에서도 안 변한다

```
A 여름 대 겨울    픽셀 평균 절대차 0.14      ← F1/F2 계절 차이(3.62)의 4%
```

패턴을 안 심은 사람은 버튼을 눌러도 그림이 그대로다. **이게 흔들리면 1~3 의 차이도
믿을 수 없다.**

### 5. 얽힌 태그와 분모가 화면에 같이 나온다

```
E 여름∩밤   n =  72
E 여름∩낮   n =  18      ← 분모가 화면에 붙어 있다
```

"여름 낮엔 하천에 안 간다" 를 n=18 에서 읽고 있다는 것이 보인다. 비율을 분모 없이 내지
않는다는 규율([territory-paint §D](../explorations/walk/territory-paint.md))의 UI 판이다.

## 설계에서 고른 것

**두 판이 같은 창·같은 축척을 쓴다.** bbox 를 공통으로 고정했다 — 각자 자기 데이터에
맞춰 확대하면 나란히 놓는 의미가 없다.

**모드 셋을 갈랐다.** `물감`(한 조건의 지도) · `존재`(간 적 있나) · `차이`(방문률 차).
존재와 차이가 다른 질문이라는 것을 UI 에서도 갈라 보여준다 — 여름 90% · 겨울 10% 인 칸은
존재로는 양쪽에 다 있어 사라지고 차이에는 +0.8 로 남는다.

**결과마다 spec 지문을 띄운다.** 판 아래에 `spec 453dbc9df867` 이 붙는다. 어떤 조건·집계로
만든 그림인지 화면에서 따라갈 수 있어야 한다는 `LayerSpec` 의 취지를 UI 까지 끌고 온 것이다.

그래서 `Projection` 에 **붓 지문(`profile_fp`)을 넣었다.** 없으면 이름이 같고 곡선만 바뀐
붓을 spec 지문이 못 잡아, 화면에 띄운 provenance 만 보고는 어느 세대의 붓이었는지 알 수 없다.
이제 `select()` 도 지문으로 세대를 고르고, 이름은 맞는데 그 세대가 하나도 없으면 **조용히
빈 지도를 주지 않고 에러다** — 빈 canvas 는 "안 갔다" 로 읽히기 때문이다.

## 알게 된 것 — 밝기 합은 그림을 비교하는 자가 아니다

검증을 자동화하면서 걸렸다. 차이 모드에서 두 판의 밝기 합이 416 대 421 로 거의 같게
나왔는데 **색은 정반대였다** — 양수 쪽과 음수 쪽이 밝기는 비슷하고 색상만 다르기 때문이다.

그래서 자를 둘로 바꿨다.

    두 그림이 같은가   →  픽셀 단위 평균 절대차 (RGB 채널별 |차|)
    부호가 반대인가    →  따뜻함/차가움 픽셀 비율

밝기 합은 애초에 **같은 총량의 전혀 다른 그림**을 구별하지 못한다. 발산 램프에서 그 약점이
드러났을 뿐이지 순차 램프에서도 옳은 자가 아니었다. 지금은 두 곳 다 MAD 를 쓴다.

## 이 실험이 말하지 않는 것

- **사용성 검증이 아니다.** 실제 견주가 이 화면을 이해하는지는 안 물었다. 여기서 판정한
  것은 "심어둔 차이가 화면에서 드러나는가" 까지다.
- **임의 질의가 되는 게 아니다.** 13 개 조합만 미리 겹쳐 두었다. UI 가 그 이상으로 보이지
  않게 만든 것이 이 실험의 설계 조건 중 하나다.
- **등급 문턱을 정하지 않았다.** `전부`/`심만` 두 단계를 눈으로 비교할 수 있게만 해 뒀다.
  등급은 이 화면에서 관찰한 뒤 별도로 정한다.
- **성능.** 장면을 미리 겹쳐 실었다(장면 918KB + 타일 775KB = 1.66MB). 조합이 늘면 이
  방식은 안 늘어난다 — 실시간 질의는 DB·API 단계의 일이다.
- **사람이 아니라 픽셀이 판정했다.** 자가 점검은 "차이가 화면에 나타나는가" 를 재지
  "그 차이가 무슨 뜻인지 사람이 아는가" 를 재지 않는다.
