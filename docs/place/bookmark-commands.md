# 장소 대화의 명시적 찜 명령 — 1단계

서버 [#445](https://github.com/SAJOYO/DAENGS_dev/pull/445), 앱
[#312](https://github.com/SAJOYO/DAENGS_APP/pull/312). 기존
[회원 시설 찜](bookmarks-api.md)을 재사용한다.

## 실행 경계

1. 앱은 발화 당시 목록·선택과 찜 컨트롤러의 계정 생애/조작 순서를 고정한다.
2. 대화 요청의 `bookmark_commands: "v1"`은 앱이 준비된 찜 명령을 실행할 수 있다는 협상이다.
3. Gemini는 `bookmark.operation=save|remove`, 원문 동작 인용, 단일 대상 표현을 제안한다.
4. 서버는 현재 저장된 결과에서 대상을 확정한다. `receipt.bookmark_command`는
   `key, name, saved`만 담고 검색 prepare에서 회원 DB를 쓰지 않는다.
5. 명령 응답은 `answer_status=none`이다. 앱은 기존 회원 찜 API의 결과를 기다려
   하트와 말풍선을 갱신한다. 서버는 찜 성공을 선언하지 않는다.

서버를 먼저 배포한 뒤 앱을 반영한다. 이전 앱은 협상 필드를 보내지 않으므로
찜 명령을 받지 않고 하트 사용 안내를 받는다. 새 앱을 이전 서버에 먼저 배포하면
추가 필드가 거절될 수 있다. DB·환경 변수·외부 API 키 변경은 없다.

## 이번에 지원하는 범위

- 현재 실제 목록의 한 장소에 대한 명시적 저장/해제. 여기·번호·정확한 상호명으로 지칭한다.
- 요청 전체가 단일 긍정 명령인지 제한된 문법으로 확인한다. 상호명에만 붙은 따옴표는
  허용하며, 문장 전체 인용·가정·부정·복합 요청은 실행하지 않는다.
- 동작 인용은 동사 구절 또는 원문 문장 전체일 수 있다. 원문에 없는 인용은 거절한다.
- 검색 조건·현재 결과·제시 이력·제외 목록은 찜 명령 준비로 변경하지 않는다.
- 평가/이미 아는 장소/정보 이의만 있는 발화는 `feedback`으로 분류한다.
  이 분류에는 필터·제외·찜 변경 권한이 없다.
- “찜하지 말고 다른 곳 보여줘”는 찜을 건드리지 않고 기존 다음 결과 탐색을 사용한다.

제한된 문법은 임의의 한국어 의도를 증명하는 장치가 아니다. 복잡한 정상 요청도
명확화로 내려갈 수 있다. 모델의 의미 분류 정확도는 별도 실제 출력 평가로 측정한다.
`feedback`의 무변경 보장은 해당 분류가 선택됐을 때의 정책 보장이다.

## 앱의 완료·충돌 계약

하트와 AI는 동일한 저장 상태 지정 명령을 호출한다. 결과는
`CONFIRMED / SUPERSEDED / UNKNOWN / FAILED`로 반환한다.
서버의 최종 목록으로 목표 상태를 확인하며, 로컬 캐시만으로 “이미 저장됨”을 단정하지 않는다.
응답 유실 시 GET으로 확인하되 반대 상태만 관측한 것으로 쓰기가 롤백됐다고 단정하지 않는다.

조회 generation은 화면 응답 제어에만 쓴다. 별도 장소별 의사 순서가 늦은 요청을
막는다. 같은 장소의 최신 직접 조작·최신 AI 의사가 우선한다. 다른 장소 조작이나
단순 새로고침은 취소 사유가 아니다. 같은 request ID의 완료 명령은 재실행하지 않는다.
일반 검색의 화면 generation이 바뀌어도 계정과 대상이 유효한 준비된 찜은 실행할 수
있으며, 예전 검색 결과나 선택으로 화면을 되돌리지 않는다. 명시적 취소·계정 종료는
이전 명령을 더 실행하지 않는다.

이는 동일 앱 실행 경로의 보호다. 이미 전송된 HTTP를 취소한다고 서버 쓰기가
롤백되는 것은 아니며, 다른 기기의 동시 변경까지 보호하는 서버 조건부 갱신은
아직 없다. 재실행 기록은 로그인 중 메모리 범위이며 앱 재시작을 넘는 명령 원장은 아니다.

## 출력 평가와 회귀

고정 문장: [bookmark-cases.json](../../backend/evals/place_conversation/bookmark-cases.json).
합성 장소 KCISA 키 A/B/C를 사용하고 실제 회원 저장·운영 DB에는 접근하지 않는다.
원문 요청·모델 출력·실행 결과와 오류 유형을 실행별 폴더에 남긴다.

```powershell
# backend/
uv run python -m daengs_evals.place_conversation.bookmarks --key-file <로컬키파일> --repeat 2
uv run pytest -q tests/place/conversation/test_bookmark_commands.py tests/place/api/test_conversation_bookmarks.py
```

평가는 찜 여부만 보지 않고 기존 필터·목록·제외·제시 이력이 변하지 않았는지도 검사한다.
제공자 실패는 incomplete로 기록하고 통과로 세지 않는다. 실제 관측 결과는
[실험 기록](bookmark-command-evaluation.md)에 정리한다.

## 후속 닫힌 작업

1. **찜 범위 대화 검색 ([#448](https://github.com/SAJOYO/DAENGS_dev/pull/448)):** [2단계 계약](saved-conversation.md). 검색 대상/공간 범위/조건을 분리한다. 주차 “필수”는
   `hard`, “우선”은 `parking`으로 기존 API에 연결한다. 찜 탭의 대화 진입과
   첫 진입만 조건 승계하는 정책은 이 단계에서 함께 변경한다.
2. **사전 조회·제안:** 현재 화면을 비우는 controller.refresh가 아닌 읽기 경로를
   사용한다. 조건·대상·시점에 묶인 제안을 만들고 제시 이력을 소비하지 않는다.
3. **조합 실행:** 찜 확인 후 다음 후보 표시. 찜 응답 불명은 현재 화면 유지,
   찜 성공 후 검색 실패는 찜 유지·검색만 재시도한다. 1단계에서는 복합 요청을
   부분 실행하지 않고 분리 요청을 안내한다.
