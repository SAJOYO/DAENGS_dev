# 소스 차단·주의 목록 (선정 단계)

**후보를 조사하기 전에 이 문서를 먼저 읽는다.** 여기 있는 도메인은 이미 한 번
걸러진 것들이고, 사유를 모르면 같은 후보가 반복해서 올라온다.

## 왜 인제스트 차단만으로 부족한가

`scripts/ingest_documents.py`의 `check_url_allowed()`가 `/premium/`·`/member/`·
`/paid/` 경로를 인제스트 시점에 막는다. 그것은 **마지막 그물**이고, 이 문서는
**선정 단계**를 담당한다. 둘의 차이가 실제로 문제가 됐다.

`mypetlife.co.kr`은 2026-08-19에 `/premium/` 문서가 수집·인제스트·Neo4j 적재까지
갔다가 2026-08-20에 사후 발견돼 제거됐다. 코드 차단은 그 사고 뒤에 생겼다.
그런데 **2026-08-26 확장 후보 조사에서 같은 도메인이 다시 후보로 올라왔고,
검색 상위에 `/premium/` 경로가 그대로 노출됐다.** 코드가 막아주긴 하지만
조사·검토 시간이 매번 다시 든다.

robots.txt로 차단된 도메인은 코드가 막지 않는다 — 그쪽은 **선정에서 거르는 것이
유일한 방어선**이다.

## 판정 기호

| 기호 | 뜻 | 취급 |
|---|---|---|
| ❌ | 차단 | 후보로 올리지 않는다 |
| ⚠ | 주의 | 올릴 수 있으나 표의 조건을 확인한 뒤 사람이 판단 |

| `wizpet.net` | `Allow:/`, 차단 없음 | |

## 갱신 규칙

1. 후보가 탈락하면 **사유와 확인일을 여기에 적는다.** 사유 없는 도메인 나열은
   다음 사람이 판단할 수 없어 쓸모가 없다.
2. robots.txt는 바뀐다. 확인일이 오래된 항목은 재조사한다.
3. **차단 목록에 있다고 영구 차단은 아니다** — `dogmaru.co.kr`의 403이 풀리거나
   `brunch.co.kr`이 정책을 바꾸면 다시 볼 수 있다. 그때 확인일을 갱신한다.
4. `docs/SOURCES.md`의 배제 정책(robots·ToS 금지, 로그인·유료 구간)이 상위
   규범이고 이 문서는 그 적용 기록이다. 정책이 바뀌면 이 목록도 다시 짠다.
