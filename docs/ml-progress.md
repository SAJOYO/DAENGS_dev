# 반려견 피부 병변 모델 — 진행상황

**목적은 진단이 아니라 screening 보조**입니다. "이건 좀 의심되니 병원 가보세요" 까지.

* 데이터: AI Hub 561 「반려동물 피부 질환」 — 반려견 + 일반카메라만
* 구조: **2-stage** — ① 정상/이상 → ② 병변 6종 (A1 구진·플라크 / A2 비듬·각질 /
  A3 태선화·과다색소침착 / A4 농포·여드름 / A5 미란·궤양 / A6 결절·종괴)
* 현재 단계: 모델링. **프론트엔드 없음**

---

## 1. 지금까지 한 것

| 단계 | 내용 |
| --- | --- |
| 전처리 | phash **dedup** → **group-aware split** (groups = `animal_id`) → ROI crop |
| 규모 | 45,885행 / 개체 2,476마리 |
| 학습 | ResNet50 / **input size 384px** / AMP + EMA + cosine warmup |
| 검사 | **scale perturbation** · **shift perturbation** 견고성, **shortcut baseline** |

**data leakage** 는 개체 단위로 막았습니다 — 같은 강아지 사진이 train/val 에
갈라져 들어가면 점수가 거짓으로 오릅니다. 분할 검증이 실패하면 학습이 시작되지
않게 해뒀습니다.

## 2. 실측 지표

> 추정치는 쓰지 않습니다. 아래는 전부 돌려서 나온 값입니다.

| | 지표 | 현재 | crop | 목표 | |
| --- | --- | ---: | --- | ---: | --- |
| Stage 2 | 병변 6종 **macro-F1** | 0.5395 | m2.5 | 0.55~0.65 | 하단 |
| Stage 2 | **scale perturbation** 하락 | 18.8% | m2.5 | <15% | ❌ |
| Stage 2 | A6(결절·종괴) recall | 0.352 | m2.5 | 0.50 | ❌ 측정 불가 |
| Stage 1 | 정상/이상 **AUROC** | 0.8192 | full | 0.80 | ✅ |
| Stage 1 | scale perturbation 하락 | 9.1% | full | <15% | ✅ |
| Pipeline | screening **recall** | 0.9501 | full+m1.5 | ≥0.95 | ✅ 재측정 필요 |

**Stage 1 은 Stage 2 의 crop 을 따라가지 않습니다.** ROI crop 을 쓰면 **crop 창
크기가 정답을 흘립니다** — 정상 bbox 면적 중앙값 0.71% vs 병변 1.25% 라 사진을
안 봐도 반쯤 맞힙니다 (**shortcut baseline** AUROC 0.6042). 게다가 그 신호는
**배포에 존재하지 않습니다** — 보호자 사진에는 bbox 가 없으니까요.

**미탐(false negative)이 오탐(false positive)보다 훨씬 나쁩니다.** screening 이라
오탐 52.9% 는 감수하고 recall 을 지키는 쪽으로 잡았습니다.

## 3. 멘토링 피드백 (2026-08-21) → 조치

| | 피드백 | 조치 |
| --- | --- | --- |
| 1 | scale 범위 **폭을 줄여**보기 | 좁힌 preset 추가해 비교 — 잡음 안, 결론 못 냄 |
| 2 | 정확도 최고 scale 로 **촬영 가이드** | 교란 표에 답이 이미 있었음 → **학습 0회로 결정** |
| 3 | **confusion matrix** 로 클래스 검토 | 혼동 쌍 상위 N개를 수치로 뽑기 — 예정. 클래스 병합은 보류 |
| 4 | **augmentation** 다양하게 | 7종 스윕 완료 → **효과 없음**으로 결론 |
| 5 | **qualitative evaluation** 필수 | 오분류 케이스 뷰어 — 후반 작업으로 예약 |
| 6 | 초반엔 **자동화 가능한 것**부터 | 수작업 큐레이션(라벨 교정·데이터 삭제)은 후반으로 |
| 7 | 학습 중 **실시간 랜덤 + albumentations** | 이미 실시간. 라이브러리 전환 완료 (22.6ms → 7.3ms) |
| 8 | **input size** 신중히 | 224 → 384 를 실측으로 결정 |

6번을 처음엔 "실험을 싸게 돌려라"로 잘못 읽었습니다. 실제로는 **작업의 종류**
이야기였습니다 — 손이 많이 가는 데이터 작업은 자동 실험을 다 짜낸 뒤에.

## 4. 결론 난 것 (다시 안 함)

| 질문 | 결론 |
| --- | --- |
| input size 를 올리면 되나 | **예** — 224 → 384 로 scale 하락 8~9%p 감소 |
| augmentation 으로 scale 을 잡나 | **아니오** — 3회 실패. `zoom_both` 는 오히려 +4.0%p 악화 |
| 흐림·노이즈가 도움되나 | **아니오** — macro-F1 −0.03. 질감이 곧 라벨입니다 |
| crop 창을 넓히면 되나 | **예** — m1.5 → **m2.5** 로 하락 −4.4%p, A1 recall +0.063 |
| 512px 로 더 올릴까 | **아니오** — crop 짧은 변 중앙값이 242px, 이미 74.6% 확대 중 |

**★ 축소는 augmentation 이 아니라 crop 으로 잡혔습니다.** `zoom_both` 는 이미지를
줄이며 정보를 버렸고, m2.5 는 더 넓은 실제 영역을 잘라 정보를 더했습니다.
→ "작게 보이는 사진에 강해지려면, 작게 만들지 말고 넓게 찍은 걸 보여줘라."

### 열어둔 문제 2개

* **남은 scale 하락은 배포 설계로 넘깁니다.** 1x 구도가 최고 점수이므로,
  **capture guideline** 으로 그 구도를 유도하면 최악 조건 자체가 안 생깁니다.
  crop 이 m2.5 로 바뀌며 "더 넓게 찍으세요" 로 문구가 바뀝니다.
* **A6 은 지금 잴 수가 없습니다.** 같은 설정인데 실행이 다르면 recall 이
  0.405 ↔ 0.344 로 움직입니다. 검증 표본이 ~256장뿐이라 2σ 가 ±0.085 —
  목표 개선폭과 거의 같습니다. **고치기 전에 재는 방법부터** (5-fold / holdout 합산).
