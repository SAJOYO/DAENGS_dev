# 공간 재료의 장면 적용 정책

각 장면은 그 시점의 스냅샷이다. 정규화된 공간 후보 중 **그 장면에 적용되지 않는 재료를
내리고, 적용되는 재료의 의미와 관계를 보존**한다. 장면의 행동·동선 패턴은 각자의 재료다.
공간 경계의 이탈·재진입 빈도를 장면의 가치나 생성 조건으로 사용하지 않는다.

[정규화](space-normalization.md) 다음 단계인 DEV #492의 실험 정책과 재생기다.
`daengs_walk.diary_space_policy`와 `diary_space_memory`에서 실행한다.
운영 미리보기·발행의 `SlotPolicy`를 자동 교체하는 변경은 포함하지 않는다.

## 재료별 정책 딕셔너리

`SpacePolicy.dictionary()`는 판정 규칙과 실험 파라미터를 함께 출력한다.
공원 거리는 입력할 때 반드시 명시한다. 아래 250m는 기존 정책과 비교하는 실험값이다.

```json
{
  "피복": {
    "적용": "장면 좌표가 실제 피복 형상 안이나 경계에 있음",
    "제외": "형상 밖임",
    "관계": "이 장면 좌표의 피복"
  },
  "공원": {
    "적용": "등록점까지의 거리가 실험값 이내임",
    "제외": "등록점까지의 거리가 실험값을 초과함",
    "거리_m": 250,
    "관계": "공원 등록점까지의 거리"
  },
  "상권": {
    "적용": "장면 좌표가 분포를 계산한 고정 조회 원 안이나 경계에 있음",
    "제외": "그 조회 원 밖임",
    "관계": "장면 좌표가 포함된 조사 범위의 업종 구성·분포"
  }
}
```

피복은 다른 재료의 성립 조건이 아니다. 공원 여러 개, 상권, 피복이 각자 유효하면 함께 남는다.
공원 종류·면적으로 경계를 만들거나, 피복이 녹지라는 이유로 공원 내부 관계를 만들지 않는다.

상권의 `fixed_query_circle`은 **고정 조사 범위를 재사용하는 이번 실험 방식**이다.
그 원 안에 있다고 등록 상가가 모인 곳 안에 있는 것은 아니다. 원래의 업종 구성·분포와
조회 중심·반경을 함께 보존하고, 현재 좌표에서 조회 중심까지의 거리만 갱신한다.
원래 등록점 최단 거리·중심 거리는 조회 중심 기준이라는 이름으로 남긴다.
장면 좌표 중심의 새 1km 분포가 필요하면 그 범위의 원자료를 다시 정규화해야 한다.

## 후보 보관과 장면 스냅샷

```text
정규화된 재료 묶음 + 사용할 수 있는 시점
  → 후보 보관
  → 장면 시점·좌표의 적용 조건 검사
  → 유효한 공간 재료와 적용 관계를 스냅샷에 고정
  → 같은 재료에 기존 용량 규칙을 적용한 비교 스탬프
```

- 좌표가 달라지면 해당 장면의 적용 관계를 다시 계산한다. 기존 스냅샷은 바뀌지 않는다.
- 공원 관계가 끝나면 그 공원만 내려간다. 피복·상권은 각자의 적용 조건으로 남는다.
- 보관된 재료는 다른 장면에서 다시 적용될 수 있다. 짧은 재진입에도 대기 조건을 붙이지 않는다.
- 위치 없는 장면의 공간 재료는 비운다. 직전 좌표를 빌려 오거나 행동핀을 만들지 않는다.
- 새 조회의 실패는 새 재료와 진단으로 처리한다. 여전히 유효한 다른 자료를 지우지 않는다.
- 후보 묶음에 명시한 `expires_at`이 있으면 그 시각부터 제외한다. 임의의 공통 TTL은 없다.
  후보 보관은 한 재생 실행 안에서만 지속되며 세션 간 캐시는 구현하지 않는다.
- 같은 대상·같은 질문에 동일한 주장은 합치고 출처는 남긴다. 서로 다른 주장은 충돌로 제외한다.
  가까움·도착 순서로 한 주장을 고르지 않는다. 명시적 만료로 충돌이 해소될 수 있다.
- 정규화 사전·재료 해시·조회 좌표·범위 종류를 검증한다. 미지원 범위를 임의로 해석하지 않는다.

`frames[].decisions`는 후보별 적용 여부와 사유, `loaded`는 유효한 재료 전체,
`changes`는 직전 스냅샷과의 차이다. 차이는 부분 갱신 확인용이며 서술·장면 생성 기준이 아니다.
`references`로 원래 후보 묶음과 재료를 역추적할 수 있고, 입력·정책은 결과에 고정한다.

## 용량 비교

적재된 유효 재료 전체를 보존한 뒤 기존 `admit()`으로 별도의 `capacity_stamp`를 만든다.
공간 3개·전체 8개·기존 역할 순서를 그대로 비교하되, 거리값은 해당 공원 실험값과 맞춘다.
따라서 거리 적용 실패와 용량 때문에 빠진 재료를 구분할 수 있다.

비교 스탬프는 공간 재료만 대상으로 한다. 실제 보드의 다른 파트와 경쟁하는 결과나,
운영 발행 스탬프를 재현했다고 해석하지 않는다. 전체 전달/일부 전달 중 최종 서술 계약을
확정하지 않았고, `capacity_stamp`에서 빠졌다고 `loaded`에서도 지우지 않는다.

## 실제 저장 동선 재생 — 2026-09-13

폰에서 앞서 확보한 서로 다른 동선 두 개의 363개·174개 GPS 좌표·순서·시각을 그대로 썼다.
각 좌표를 **공간 적용 정책을 검사하는 스냅샷 지점**으로 사용했다. 일기 장면을 537개 만든
실험은 아니다. 실제 생성·행동·동선 패턴의 서술은 이번 실험에 없다.

- 상권은 당시 저장한 500m 조회 응답을 보존했다. 1km로 확장한 자료인 것처럼 쓰지 않았다.
- 공원은 저장된 전국 목록에서 조회 중심 1km 내 후보를 정규화했다.
- 피복은 각 동선의 여섯 지점을 균등 표본으로 지정해
  [공식 2025년 레이어](https://aid.mcee.go.kr/api/land.do)를 조회했다. 12건 중 11건을 받았고,
  마지막 한 건은 제한 시간 내 확보하지 못한 상태를 보존했다. 각 결과는 해당 표본 시점부터
  후보로 제공했다. 미조회 영역의 피복은 채우지 않았다.
- 현재 확보한 환경 자료를 과거 동선에 대입한 재생이다. 산책 당시 환경을 관측했다는 뜻은 아니다.
- 공공 원자료·폰 좌표·상세 결과는 비공개 작업 폴더에 보존하고, 아래 집계와 합성 재현 입력을
  저장소에 남겼다. 정상 응답을 얻기 위해 원래 실패 기록을 바꾸지 않았다.

| 동선 | 공원 거리 실험값 | 공원이 적용된 지점 | 최대 유효 공간 재료 | 3개 용량으로 재료가 빠진 지점 |
| --- | ---: | ---: | ---: | ---: |
| A · 363점 | 100m | 72 | 3 | 0 |
| A · 363점 | 250m | 348 | 4 | 101 |
| A · 363점 | 500m | 363 | 7 | 350 |
| B · 174점 | 100m | 0 | 2 | 0 |
| B · 174점 | 250m | 41 | 3 | 0 |
| B · 174점 | 500m | 174 | 4 | 152 |

A의 250m 실험에서 빠진 것은 각 지점의 추가 공원 후보 한 개씩이다. 조건에 맞는 재료도
공간 3개 제한 때문에 빠질 수 있음을 확인했다. 이 결과로 거리값이나 최종 전달 개수를
정하지 않는다. 상권은 두 동선의 모든 지점에서 고정 조회 범위 재료로 남았으며,
각 지점의 피복 적용 여부는 다른 재료의 유지에 영향을 주지 않았다.

집계 정본은 [실제 재생 요약](../../backend/evals/walk-diary/space-policy-v1/real-summary.json),
실행 가능한 예제는 [합성 입력](../../backend/evals/walk-diary/space-policy-v1/input.json)이다.

## 비용과 검증 범위

실제 도로 응답에는 약 7~10MB의 형상과 수천 개의 구멍이 포함됐다. 재생기는 동일 형상을
한 번 검증·준비하고, 각 좌표에서 경계 상자로 관련 링을 추린다. 원래 ray-crossing·경계
포함 규칙을 보존하며 형상 수정·단순화·새 GIS 의존성은 추가하지 않는다.

준비 후 한 좌표에서 저장된 고유 후보 전체를 검사한 시간의 95백분위는 A 5.206ms,
B 4.457ms였다. 준비 시간은 0.220초·0.142초였다. 이는 적용 함수만의 측정으로,
API·입력 역직렬화·검증·해시·스탬프 생성·저장은 제외한다.
전체 재생은 입력 검증과 스탬프 생성을 포함해 A 약 10~11.4초, B 약 5.6~6초였다.
외부 수집까지 포함한 5초 보장을 검증한 결과는 아니다.

실제 형상 4개×좌표 4개, 합성 형상의 경계·구멍·자기 교차·두 CRS에서 원래 판정과 비교했다.
부분 갱신·공존·위치 없음·명시적 만료·충돌·출처 병합·변조 차단·용량 손실도 검증한다.
같은 좌표들 사이의 시간 간격만 바꾸어도 적용 재료가 같다는 회귀 검사를 포함한다.

실행 명령과 파일 형식은 [코드 옆 안내](../../backend/src/daengs_walk/SPACE_NORMALIZATION.md)에 있다.
