# 관계 기반 산책 일기 — 기획·구현 기준

## 기준과 범위

기준은 사용자가 제안한 **사실 저장과 서술 슬롯의 분리**, 그리고 제공한 `산책일기_전체실험.html`의 로컬 v4 구현과 `문서/산책일기_판단과구현방향.md`다. 원격 `feat/relational-diary-skeleton`의 `92f59f9`는 v2였으므로 첨부 v4를 잃지 않고 이어간다. 과거 실험의 실패·원문·당시 평가는 수정하지 않는다.

이 문서는 이번 수정의 기준이다. 기존 README에 누적된 과거 단계 설명을 새로운 지시로 섞지 않는다. 새로운 개인 프로필, 장기 기억 장소, 통합 장면 에이전트, TMAP 의존성을 추가하지 않는다.

## 바꾸지 않는 기획

장소별 원자료와 정규화된 사실은 모두 보존한다. 서술 생략은 사실 삭제가 아니다. 처음에는 현재 공간을 소개하고, 뒤에서는 현재 공간과 앞선 공간의 **차이와 관계**를 중심으로 서술한다. 같은 배경을 매번 재소개하지 않는다.

공간과 행동은 독립적으로 작성한다. 행동은 현재 핀의 주체·행동·시각과 현재 공간만 사용한다. 핀 시각의 기기 이동은 별도 주체이며 반려견 행동의 원인·기간이 아니다. 행동핀은 반복돼도 각각 남는다. 메모·사진 원문은 생성·검수·제목 입력에 넣지 않고 그대로 보존한다.

연결된 기존 GPS 관측은 두 기록 위치 사이 이동을 설명할 근거다. 그 근거를 특정 도로의 통과, 숲 진입, 중간 전체의 피복으로 확대하지 않는다. 100m마다 카드나 호출을 만들지 않는다. 날씨의 카드별 반복을 새로 넣지 않는다.

서버는 대상·관계·범위·작성 과제를 정하고, 모델은 문장을 쓴다. 서버가 완성 문장 템플릿을 만들어 LLM 성과로 제시하지 않는다.

## 관계 계약

`record_location`은 같은 산책의 시간순 기록 위치에 연결된 정규화 공간 배경의 차이다. 두 위치는 관측 위치이고 보고된 정확도 범위가 겹치지 않아야 한다. 이는 GPS의 절대 정확성을 증명하거나 공간 객체의 동일성을 판정하는 계약이 아니다. 자료 관측일이 없으면 null 그대로 보존한다.

`location`은 비교 가능한 원자료 계열·동일 관측 시점·구별되는 대상과 공간 범위가 있는 속성 비교다. `observation_time`은 같은 원자료 대상의 실제 관측 시점 비교다. 조회 시각이나 기록 시각만 바뀌었다고 장소 자체의 변화로 만들지 않는다.

유효한 관계가 없으면 현재 맥락만 작성한다. 위치나 자료 누락을 떠남으로 바꾸지 않는다. GPS 연결은 관계와 함께 전달하며 관계 입력을 대체하지 않는다. 변경된 세 역할 중 앞의 두 개만 잘라내던 부분은 제거한다.

## 실제 실행 경로

```text
기존 준비·정규화·GPS 측정
  -> prepare_relational_diary
  -> 공간 관계와 GPS 연결을 함께 가진 계획
  -> write_with_short_memory
     -> 공간 작성 / 현재 행동 작성 (입력 독립)
     -> 참조 검사
     -> 별도 의미 검수
     -> 채택된 소개의 전달 상태 갱신
  -> assemble_receipt
  -> 채택 본문·기기 관측으로 제목 작성 및 검수
  -> save_skeleton / read_skeleton
```

숏메모리는 앞선 두 장면의 원자료 공간 맥락·계획·전달 상태만 받는다. 생성문·이전 행동을 사실로 재사용하지 않는다. 소개가 실패했으면 다음 동일 배경에서 현재 소개를 복구한다. 성공한 소개에서 선택하지 않은 **선택적 자료**를 모두 말하게 하려고 다시 호출하지 않는다. 실제 검수된 역할과 소개된 맥락의 서명을 따로 기록하며 모든 사실이 전달됐다고 선언하지 않는다.

## 검수는 이번에 추가한 구현 결정

ID 검사만으로 문장의 의미를 통과시키지 않는다. 같은 배포 모델에 별도 검수를 요청하되 검수기는 문장을 수정·생성하거나 다음 기능을 계획하지 않는다. 주체, 관계 축, 공간 범위, 미제공 경험, 필수 의미, 문장 가독성을 확인한다. 거절·검수 실패 시 후보 문장은 본문에 채택하지 않고 원문과 실패 이유를 저장한다. 자동 재작성·무제한 재시도는 없다.

**검수 결과는 `model_review_not_proof`다.** 모델 검수도 틀릴 수 있다. 오프라인 테스트의 검수 응답은 주입한 테스트 더블이며 실제 Gemini 판별력 측정이 아니다. `review=False`는 명시적 비교 실험용으로 `unverified`를 남긴다.

## 호출과 실패

작성·검수·제목 모두 하나의 호출 조정기를 사용한다. 실험 기본값은 동시 1개, 응답 완료 후 최소 10초다. 429가 발생하면 그 실행의 후속 호출을 멈춘다. 503을 포함한 실패에 숨은 재시도는 하지 않는다. 최대 호출 수를 넘으면 남은 부분은 실패로 기록한다.

참조 검사를 통과한 각 본문과 제목에 검수 1회가 추가된다. 공간 3개·행동 1개·제목 1개가 모두 반환되는 정상 경로는 **작성 5회 + 검수 5회 = 10회**다. 소개 복구가 생기면 해당 작업의 작성·검수가 추가된다. 이것은 원래 5회보다 호출이 늘어나는 설계 선택이며 비용 감소라고 주장하지 않는다. 실제 토큰·비용·지연 비교는 새 모델 실험 전에는 미확인이다.

## 저장과 호환

새 발행 형식은 v5다. v2/v3/v4 저장본은 다시 생성하지 않고 그대로 읽는다. 사용자 원문, 전체 준비본, GPS 구간 참조, 공간 근거, 최종 계획, 실제 요청·스키마·원문·검수 결과·호출 수가 함께 저장된다. 다른 장면의 현재 공간·도로·핀 또는 출처와 다른 관계를 재해시해 넣어도 검증에서 거절한다.

`save_skeleton`은 새 파일만 생성한다. 기존 결과를 덮어쓰지 않는다. 여기의 파일 저장은 운영 DB 구현이 아니다.

## 검증 상태와 완료 조건

이번 환경에서 확인한 것은 새로운 회귀 테스트와 저장된 준비본을 통한 실제 코드 경로다. GPS 구간 테스트는 실제 커널의 `WalkEvidencePoint` 계약과 합성 canonical segment fixture를 사용하며, 측정 커널 전체를 재실행한 테스트로 부르지 않는다.

다음 항목은 **완료됐다고 주장하지 않는다**: 새 Gemini 출력의 품질·검수 정확도, 전체 백엔드 통합 테스트, 실측 폰 산책, 운영 API/DB/APP 전환. 이 변경은 opt-in 스켈레톤에 한정한다. 이미 동작하는 운영 기본 경로를 몰래 바꾸지 않는다.
