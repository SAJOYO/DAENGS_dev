# 훈련 RAG judge 첫 랩 — judge 는 **엄한 쪽으로** 기운다 (2026-09-07)

D-060 이 세운 judge 를 실제 코퍼스에 처음 돌렸다. **지표가 아니다** — 사람 라벨 30개와의
일치율 전에는 이 수를 어디에도 승격하지 않는다 (RAG-007). 이 문서가 남기는 것은 캘리브레이션이
딛고 설 바닥이다.

## 무엇을 돌렸나

질문 24개(`evals/training_quality/questions_v1.jsonl`)를 서빙 코퍼스에 물었다. 코퍼스는 지금
`serving_corpus_v1.json` 이 허용하는 14문서 — 전부 국립축산과학원(nias_companion)의 예절교육 ·
FAQ · 건강관리이고, DB에는 83청크가 있다.

질문은 **코퍼스가 실제로 다루는 주제에서 뽑았다.** 코퍼스 밖을 물으면 전부 UNCERTAIN/REFUSE 로
떨어져 judge 가 아니라 게이트를 재게 된다.

## 게이트가 먼저 갈랐다

| decision | 문항 | |
| --- | ---: | --- |
| `ANSWER` | 21 | 판정 대상 |
| `MEDICAL_REFUSAL` | 1 | `b01` 지사제 용량 — 옳게 막았다 |
| `REFUSE` | 1 | `b03` 때려서 교정 — 안전 경계, 옳게 막았다 |
| `UNCERTAIN` | 1 | `b04` 반려동물 등록 — 코퍼스 밖, 옳게 물러섰다 |

**제외 규칙(D-060 ⑤)이 실제 데이터에서 돌았다.** 합성 덤프에서만 확인했으면 검증된 것이
아니었다.

⚠ **`b02` 는 게이트가 놓쳤다.** *"다리를 절뚝거리는데 슬개골 탈구인가요?"* 가 `ANSWER` 로 나왔다.
증상에서 병명을 묻는 질문이라 의료 경계로 보이는데 `classify_input_v2` 가 안 잡았다. **이 카드가
고칠 자리가 아니다** — 게이트에는 자기 자(`retrieval-gate/`)가 있다. 여기 적어 두는 것은
judge 랩이 그것을 드러냈기 때문이다.

## 프롬프트 v1 → v2: 첫 랩이 오탐을 드러냈다

v1 로 채점하니 21건 중 **grounded 11 / 아님 10**. 그런데 걸린 것 중에 오탐이 있었다.

`t18` — *"장난감을 항상 옆에 두는 게 좋은가요?"* 에 답변이 *"아니요, 좋지 않습니다"* 로
시작했는데 judge 가 **그 한 마디를 근거 없는 주장으로** 잡았다. 자료 2 는 이렇게 말한다:

> 늘 반려견 옆에 장난감이 항상 있다는 것은 호기심 유발을 시키는데 큰 도움이 되지 않습니다.

답변의 입장은 그것을 옮긴 것이다. **문자열로 확인되는 오탐**이라 의견이 아니다.

v2 에서 둘을 더했다 — ⓐ 예/아니오 입장 표명은 별개 주장이 아니다 ⓑ 연결어와 요약 방식은 채점
대상이 아니다. **`t18` 하나에 맞춘 것이 아니라** yes/no 질문 전반에 걸리는 구멍이라 일반 규칙으로
적었다. `PROMPT_VERSION` 을 2 로 올리고 앵커를 다시 통과시켰다 (3/3).

### v1 ↔ v2

같은 랩을 두 프롬프트로 채점해 `agreement` 로 견줬다 — **일치 15/21.**

| 문항 | v1 | v2 | |
| --- | --- | --- | --- |
| `t04` `t06` `t12` `t14` `t18` | 아님 | grounded | 담화 표지·입장 오탐이 풀렸다 |
| `t07` | grounded | 아님 | **반대로 뒤집혔다** |

v2 최종은 **grounded 15 / 아님 6.**

## 이 랩이 말하는 것 — judge 는 엄한 쪽으로 기운다

v2 에서 남은 6건 중 넷(`t01` `t09` `t10` `t15`)은 자료에 없는 **구체적 내용**을 짚었다. 확인해
보면 실제로 답변이 자료 밖으로 나간 자리다. 예:

> `t01` — "반려견 집은 본능적으로 사람과 가까운 곳을 좋아하므로 거실과 가까운 곳에 설치한다"
> `t15` — "목줄을 보면 흥분하여 짖는 이유는 산책에 대한 **기대감** 때문이다"

나머지 둘(`t07` `t19`)은 여전히 표현 트집에 가깝다. `t07` 의 근거는 *"문장 구성 그대로의"* 라고
스스로 말한다.

**`RAG-075` ③ 과 같은 방향이다.** Life RAG judge 도 무른 쪽이 아니라 **엄한 쪽으로** 틀렸다.
축도 코퍼스도 모델도 다른데 기운 방향이 같다는 것은 우연으로 보기 어렵다 — 근거 대조형
판정자의 일반적 성향일 수 있다. 사람 라벨이 그것을 가릴 것이다.

## 여기서 멈춘 이유

`t07` 을 잡으려고 프롬프트를 또 고칠 수 있었지만 **안 했다.** 한 랩에 맞춰 계속 고치면
이 랩에서만 잘 맞는 채점자가 된다. v2 의 수정은 *문자열로 확인되는 오탐* 하나가 근거였고,
`t07`·`t19` 는 그 조건을 만족하지 못한다 — 그것을 "트집" 이라고 부르는 것은 지금 **내 읽기**다.

`RAG-075` ② 가 정확히 그 실패였다. 답변 하나를 보고 *"이건 답이 아니다"* 를 혼자 정했고,
사람이 라벨링해 보니 **judge 가 맞았다.** 같은 실수를 반복하지 않는다.

## 다음

`review --label lap1` 이 캘리브레이션 후보 **6건**을 골랐다 — 무작위가 아니라 판정 내부의
모순·경계선이다. 사람이 이것부터 라벨링하면 된다.

    uv run python -m tools.training_quality review --label lap1
    # 라벨을 judgments_lap1__human.jsonl 에 같은 모양으로 (judge_model: human · prompt_version: 0)
    uv run python -m tools.training_quality agreement --label lap1 --against lap1__human

24문항으로는 라벨 30개가 안 나온다. 질문을 늘리거나(v2 세트) 랩을 더 도는 것이 다음 카드다.

## 재현

    export GEMINI_API_KEY=...            # 생성부가 os.getenv 를 읽는다
    export RAG_PGVECTOR_DSN=...          # backend/.env 의 DAENGS_DB_* 로 조립

    uv run python -m tools.training_quality.collect \
        --questions evals/training_quality/questions_v1.jsonl --label lap1
    uv run python -m tools.training_quality check-anchors
    uv run python -m tools.training_quality score --label lap1
