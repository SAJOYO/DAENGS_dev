# 이동 재료 v5 · 실제 Gemini 서술 검토

2026-09-14. #520의 이동 재료 조립과 공원 고유명 제거를 적용하고,
`gemini-3.1-flash-lite`로 기존 양재 8개 장면을 한 차례 작성했다.
공공자료는 `public-02`의 실제 수집 스냅샷이며 GPS·시간·행동·메모는 기존 가상 입력이다.
새 공공 API·TMAP·운영 DB 호출은 없다. 생성 본문은 수동으로 고치지 않았다.

**판단: 공원 이름 제거와 숫자 없는 활동 입력은 연결됐다. 하지만 지금 본문은
서비스 품질로 완료할 수준이 아니다. 이동 순서를 나열하는 문체와 근거 없는 해석이 남았다.**

## 실행 결과

- 공간 8개·활동 8개 응답 채택. 형식·인용 검사를 통과했다는 의미다.
- 마지막 전체 맥락 제목 배치 1개는 `provider_failed`. 모든 제목은 기본값이다.
  저장된 실패 코드만으로 공급자 오류·제한 등 상세 원인을 단정할 수 없다. 재호출하지 않았다.
- 자료·슬롯을 먼저 준비하는 기존 `--prepared-input` 품질 실행, 전체 기록 13.125초.
  공공 수집부터 시작하는 실제 발행 지연 측정은 아니다.
- SDK 재시도 설정은 1회 시도이며 이번 결과를 고치기 위한 추가 생성은 하지 않았다.
- canonical GPS 재생·장면 연결·원자료 버전·원문·관측 코어·슬롯 재생 일치.
- 실제 결과를 저장 형식으로 변환한 뒤 다시 읽어 보드 일치. 이전 v4 저장본도 현재 리더로 읽음.
- 공원 정규화 변경에 직접 연결되는 정규화·카드 작성·저장 경계 테스트 47개 통과(9.29초).

## 입력과 문장의 대조

| 장면 | 실제 출력 일부 | 입력을 기준으로 한 판단 |
| --- | --- | --- |
| 전체 공간 | “근처에 공원이 자리 잡고 있었다” 등 | 8개 모두 공원 고유명이 없다. 공원 종류·정확한 거리도 전송하지 않았다. 원자료는 내부에 남았다. |
| 3 공간 | “기록 좌표는 지도상 숲으로 분류되었으며 근처에 공원 등록 지점이 있었다” | 지도 관계를 보존했으나 일기 본문에 내부 표현이 그대로 나온다. 고유명 제거만으로 자연스러움까지 해결되지는 않았다. |
| 1 활동 | “산책의 시작에서 … 일정하게 나아갔다” | 입력은 한 이동의 시작 부분과 대체로 곧은 진행이다. 일정한 속도 근거는 없고, 모델은 산책 시작 역할도 받지 않았다. |
| 2 활동 | “길 끝에서 속도를 줄였다” | 상대 저속을 감속으로 바꿨다. 실제 도로의 끝이라는 근거도 없으며 입력의 끝부분은 관측 이동 구간의 범위다. |
| 2 활동 | “보리가 냄새를 맡는 동안 느린 걸음으로 구간을 지났고” | 냄새 맡기 기록 시각과 느린 이동의 연결은 사용했다. 그러나 행동의 지속시간은 주어지지 않아 ‘동안’으로 구간 전체와 겹친다고 서술하는 것은 과장이다. |
| 4 활동 | “평소보다 느린 속도” | 비교 기준은 이번 산책 내부다. 개인의 평소 걸음으로 넓혔다. |
| 4 활동 | “중간 일부 구간을 곧게 지나쳤다” | 범위 설명이 그대로 문장이 되어 부자연스럽다. 좁은 범위의 머묾·직선 근거도 장황하게 함께 나열한다. |
| 5 활동 | “산책의 시작 부분에서 … 산책을 마쳤다” | 실제로는 8개 중 5번째다. 입력의 개별 이동 시작/끝 범위를 전체 산책의 시작/종료로 확대했다. |
| 6 활동 | “직선적인 이동을 유지하며 속도를 높였다” | 이 활동 입력에는 속도 재료가 하나도 없다. 만들어낸 속도 변화다. |
| 7 활동 | “곧은 길을 두 차례 더 걸으며 산책을 마쳤다” | 중간 장면의 이동 조각을 세어 나열하고 산책 종료까지 추가했다. |
| 8 공간 | “풀밭 위를 지났으며” | 지도상 피복을 실제 통과 경험으로 확대했다. 공간 작성은 동선을 받지 않으므로 이런 통과 행동을 만들 근거가 없다. |

공간 본문은 8개 모두 동 이름으로 시작하고, 8개 모두 공원을 언급했다.
공원의 존재를 간단히 쓰는 변화는 좋지만 모든 장면에서 같은 배경을 반복하니 여전히 단조롭다.
활동도 매번 직선·좌우 방향을 빠짐없이 옮기는 경향이 강하다.
입력의 숫자는 사라졌지만 분석용 표현과 구간 경계는 여전히 본문에 영향을 준다.

이번 양재 경로의 최종 활동 재료에는 굽이와 상대 고속이 없다.
고속이 없는 것을 결함으로 보거나 임계치를 바꾸지 않았다.
굽이와 속도를 결합한 실제 문장 품질은 이 실행으로 평가할 수 없다.
앞선 형상 테스트의 굽이 판정 성공과 이번 실제 Gemini 서술을 혼동하지 않는다.

## 다음 변경에 대한 의견

새로운 수집이나 속도 정책 변경보다 **작성기에 주는 의미의 범위와 문장 선택**을 먼저 다듬는 편이 맞다.

1. 이동 조각의 시작/끝은 한 구간 안의 범위다. 전체 산책 시작/종료 역할과 명시적으로 구별한다.
   필요한 범위만 전달하고, 분석에서 잘렸다는 사정을 문장 소재로 만들지 않는다.
2. 상대 저속은 그 구간의 느린 걸음이라는 재료다. 감속·평소 속도와 혼동하지 않도록 재료 표현을 다듬는다.
   재료가 없는 속도를 채워 쓰는 오류는 현재 짧은 프롬프트만으로 막히지 않았다는 점도 남긴다.
3. 직선 조각을 전부 문장으로 펼치는 대신 해당 장면의 주요 이동 관계를 간결하게 쓴다.
   분석 근거를 삭제하는 것과 문장에서 매 항목을 나열하지 않는 것은 별개다.
4. 공간 관계의 한계를 유지하되 ‘등록 지점’ 같은 자료 설명을 사용자 본문으로 옮기지 않도록 다듬는다.
   현재 공간·활동 두 작성기의 행동 서술 중복도 같이 본다.

이 의견에 따른 추가 프롬프트 수정·재생성은 이번 실행에 섞지 않았다.

## 재현과 파일

`backend/`에서 새 출력 폴더에 `public-02`의 `input.json`, `backgrounds.json.gz`,
`map.json`, `source-lineage.json`을 복사한 후 다음을 실행한다. 기존 결과는 덮지 않는다.

```powershell
uv run --no-sync python -X utf8 tools/run_diary_route_scenario.py generate --prepared-input --env-file <공급자 키 파일> --output <새 출력 폴더>
uv run --no-sync python -X utf8 tools/run_diary_route_scenario.py verify --output <출력 폴더>
uv run --no-sync python -X utf8 tools/run_diary_route_scenario.py render --output <출력 폴더>
```

- [본문 원문](diary.md), [실제 요청과 채택 응답](llm-requests.json), [요약](summary.json).
