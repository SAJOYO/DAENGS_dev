# 동선 패턴 정규화와 장면 적용

2026-09-14 #508의 신규 기본 작성은 아래 판별기를 재사용해 **동선과 속도를 통합 슬롯으로**
전달한다. [현재 활동 서술](diary-activity.md)을 먼저 읽는다. 아래 개별 패턴 후보·용량 경쟁·
특별한 순간 제외 정책은 명시적인 과거 슬롯 정책의 경로이며 신규 통합 슬롯과 구별한다.

GPS의 동선 패턴을 DEV에서 판별·정규화하고, 이미 선택된 장면의 공통 슬롯 준비 경로에
연결한다. 공간은 API, 동선 패턴은 GPS, 행동은 선택적 행동핀 앵커다.
행동핀 없는 장면도 공간과 동선 패턴을 받을 수 있다. 새 가짜 행동핀을 만들지 않는다.

```text
검증된 저장 동선 → 기존 판별기 → 유한 의미 사전 + 관측 구간·꼭짓점
  → 선택된 장면의 위치·시각에 적용되는 후보
  → 기존 제외·충돌·용량 → 장면 스탬프
  → 정규화 의미·적용 관계 → 기존 writer·발행·저장·APP 표시
```

## 이식한 것

GEO [d844fad의 판별기](https://github.com/rkbuhtig/DAENGS_geo/blob/d844fad86353d99af7f0c0011f6e1b0a5a7cf3c7/scripts/spikes/diary_storyboard/how_materials.py)와
[장면 결합 실험](https://github.com/rkbuhtig/DAENGS_geo/blob/d844fad86353d99af7f0c0011f6e1b0a5a7cf3c7/scripts/spikes/diary_storyboard/how_stamps.py)이 출처다.
DEV 실행 중 GEO를 import하지 않는다. 이전 HOW 명칭은 출처·동등성 fixture에만 남긴다.

| 케이스 | 미리 정의한 `material` |
| --- | --- |
| `local_stay` | `{"이동 상태": "한곳 주변에 머묾"}` |
| `straight_run` | `{"경로 형태": "대체로 곧게 이어지는 이동"}` |
| `turn_left` | `{"방향 전환": "왼쪽으로 꺾이는 이동"}` |
| `turn_right` | `{"방향 전환": "오른쪽으로 꺾이는 이동"}` |
| `turn_reverse` | `{"방향 전환": "진행 방향이 반대로 바뀌는 이동"}` |
| `retrace` | `{"이전 경로와의 관계": "방금 지나온 구간을 되짚는 이동"}` |

기록 기기의 움직임이다. 머묾을 냄새 맡기로 바꾸거나 행동핀의 행동을 추측하지 않는다.
직선과 되짚기는 서로 다른 특징으로 함께 성립한다. 반전만으로 되짚기를 만들지 않는다.

기존 판별 수치를 보존했다. 정확도 상한 20m·속도 상한 4m/s, 단순화 최소 8m,
국소 체류의 상자 대각선 20m·30초·5개 fix·성긴 이동량 속도 0.4m/s,
직선 최소 40m, 회전 앞뒤 각각 최소 30m·45도, 반전 150도,
되짚기 최소 40m·기본 허용 거리 10m다. 실제 허용 폭에는 원래 정확도 기반 보정도 적용한다.
합성 실험 기준이며 실기기에서 확정한 임계값은 아니다.
완만한 곡선의 누적 회전, 여러 모서리에 걸친 되짚기, 배회 분류는 추가하지 않았다.

## 적용 범위와 스냅샷

`support`는 판별에 사용한 관측 구간이며 `anchor`는 실제 관측 fix다.
특히 **회전의 앞뒤 긴 구간 전체가 회전하는 시간이라는 뜻은 아니다.**

- 기존 `VerifiedBoardRoute`로 산책·세션 시각·계산 버전·원본을 확인한다.
- canonical 단절과 패턴 판별의 추가 정확도·속도 거절을 유지한다. 단절을 다시 잇지 않는다.
- 장면 위치와 시각에 대응하는 패턴 구간이 하나일 때만 연결한다. 위치 없음·임시 위치·
  낡은 위치·다른 장소·대응 불명은 해당 재료를 제외하고 행동 코어는 유지한다.
- 직선·머묾·되짚기는 해당 support 안에서만 적용한다. 직선의 시작과 끝에 놓인 장면은
  `starts_at_scene_point`·`ends_at_scene_point`로 관계를 구별한다.
- 회전은 support 안이라는 조건에 더해 관측 꼭짓점과의 시차 20초·거리 15m를 확인한다.
  이 두 기본값도 GEO 결합 실험에서 가져왔다. `near_observed_turn_vertex`라는 관계를 전달한다.
- 새 패턴은 직전 구간으로 이월하지 않는다. 기존 체류·상대 속도 관측의 직전 허용 정책은 그대로다.
- 특별한 순간의 자유 서술에는 새 동선 패턴을 추가하지 않는다.

산책 종료 후 저장 동선의 관측 근거를 사용하는 경로다. 회전 판별에는 꼭짓점 이후 관측도
필요하므로, 실시간으로 그 시각까지 알 수 있었던 것만 조회하는 도구와 구별한다.
장면은 스냅샷이다. 공간 이탈·재진입 빈도나 잠시 기다리는 규칙으로 장면 가치를 평가하지 않는다.

## 적격성과 용량

한 패턴은 한 `motion` 후보, 역할은 기존 `scene_motion`이다. 케이스를 한 후보로 묶어
용량 제한을 우회하지 않는다. 기존 동선 용량 1개·전체 8개와 기존 관측의 정렬은 보존했다.
따라서 유효한 직선과 되짚기가 있어도 기본 용량에서는 하나가 빠질 수 있다.
이는 판별 실패와 구별해 `part_capacity`로 기록한다. 기존 체류·상대 속도와의 용량 경쟁도 남는다.

추가된 패턴끼리는 별도의 서술 가치 우대를 두지 않는다. 최종적으로 어떤 재료를 모두 또는
일부 전달할지, 기존 관측과 중복·용량을 어떻게 조정할지는 후속 정책 실험이다.
공간 재료의 적용은 [공간 정규화](space-normalization.md)와 [공간 정책](space-policy.md)을 따른다.

## 작성 입력과 저장

LLM이 받는 패턴 재료 예시:

```json
{
  "material": {"이전 경로와의 관계": "방금 지나온 구간을 되짚는 이동"},
  "relation": {"kind": "scene_within_pattern_support", "meaning": "이 장면 지점을 포함하는 관측 구간"},
  "subject": "recording_device",
  "action_meaning": "not_inferred"
}
```

원본 구간·꼭짓점·거리·각도·품질과 사전·정책 버전은 내부 근거에 남는다.
새 패턴의 모델 입력에는 원본 GPS·시각·판별 수치를 넣지 않는다.
기존 다른 관측의 작성 투영까지 이번에 바꾼 것은 아니다.
APP에는 기존 `interpretation`·`temporal_relation` 표시 필드도 보존해 새 앱 스키마가 필요 없다.

미리보기와 실제 생성은 `prepare_board_slots`를 공유한다. 공간 수집 후 다시 준비할 때도
동일 정책·동선을 사용한다. 발행한 스탬프와 본문은 기존 JSONB 영수증으로 보존한다.
설정 변경으로 최신 배경과 차이가 나면 `background_update_available`이 바뀔 수 있지만,
조회·재요청만으로 기존 일기를 재작성하지 않는다. DB 스키마 변경은 없다.

후속 [장면 서술 구조](scene-writing.md)는 일반 장면의 완결된 본문과 선택적 행동을 결합한다.
특별한 순간 원문은 보존한다. 실제 문장 품질과 전체 일기 생성은 별도 작업이다.

## 활성화와 확인 범위

기본값은 비활성이다. `DAENGS_WALK_DIARY_ROUTE_PATTERNS_ENABLED=true`면 새 기본 보드 생성과
정책을 생략한 미리보기에서 활성화한다. 명시적으로 보낸 정책과 저장본의 정책은 덮어쓰지 않는다.
미리보기 요청의 `policy.route_patterns: {}`로만 켤 수도 있다.
실행·재생 방법은 [코드 옆 안내](../../backend/src/daengs_walk/ROUTE_PATTERNS.md)를 따른다.

- 합성 동선 10종의 분류·측정값·support·꼭짓점·품질과 canonical 품질이 GEO와 같다.
  식별자와 HOW→route pattern 네임스페이스 변경만 비교에서 구별했다.
- 기존 폰 동선 363개·174개 fix도 같은 항목이 모두 일치했다. 정규화 계산만 0.0147초·
  0.0061초였다. canonical 계산·파일 읽기·API·LLM 시간은 포함하지 않는다.
  공개 [집계](../../backend/evals/walk-diary/route-patterns-v1/phone-summary.json)에 실제 좌표는 없다.
- 행동핀 없는 장면의 결합, 회전 꼭짓점과 support 구별, 호환 패턴 동시 적재,
  용량 손실, 위치·품질 단절, 공간 수집 뒤 미리보기/발행 동일 스탬프를 검사했다.
- 가짜 provider·DB 경계의 HTTP 검사로 작성 입력·발행 영수증·재조회·설정 변경 후 원문 보존을 확인했다.
  실제 Gemini 문장 품질이나 운영 서버·폰에서 활성화한 결과는 아니다.
