# 원좌표를 지우고 나면 무엇을 남겨야 하나 — 후보 셋의 실측

2026-08-26 스파이크. 재현:

```bash
uv run python -m scripts.spikes.territory_paint.persona_year --cache osm.json --json personas.json
uv run python -m scripts.spikes.territory_paint.storage_candidates --personas personas.json --cache-sheets sheets.pkl
```

코드는 `scripts/spikes/territory_paint/storage_candidates.py`, 갈래는
[territory-paint §A](../explorations/walk/territory-paint.md).

## 왜 쟀나

결정 #57 이 연속 궤적을 finish 직후 purge 한다. 그러면 셀로판을 나중에 다시 만들 근거로
무엇을 남기나. territory-paint §A 가 후보 셋을 열어 뒀는데, 거기 적힌 크기는 **추정이지
실측이 아니다.**

| | §A 의 추정 |
|---|---|
| A. 단순화 궤적 | ~80점 |
| B. 셀 맵 + 셀별 시각 | ~200행 |
| C. 셀 맵, 집계만 | ~200행 |

되돌릴 수 없는 경계를 추정치 위에 그을 수 없어서 실제로 잰다. **여기서 고르지 않는다** —
숫자만 놓는다. 고르는 것은 결정 문서의 몫이다.

## 재는 방법

페르소나 실험이 이미 만들어 둔 산책 **98회**(개 한 마리분, `persona_year`)를 그대로
쓴다. 격자 15 단위(실제 셀 11.9m), 붓 `계단 3·8·20`. 연 환산은 하루 2~3회 = **1,000회**.

축 넷을 잰다. **이름을 좁게 붙였다** — 첫 판에서 셋을 실제로 재는 것보다 넓게 불렀고,
리뷰에서 셋 다 잡혔다.

| | 정확히 무엇을 재나 | 첫 판에서 뭐라고 불렀나 |
|---|---|---|
| 저장량 | 남겨야 할 **스칼라 개수**와 연 환산 | "크기" — bytes 로 읽힌다 |
| 재투영 | 다시 칠했을 때 **칠해진 칸 집합**의 Jaccard 거리 | "재도색 오차" |
| 인접 구조 | 칸 집합에서 경로의 **공간 인접 관계**를 되짚을 수 있나 | "순서 복원" |
| 집 노출 | 그 형태만으로 집을 얼마나 정확히 찍나 | 그대로 |

숫자는 하나도 안 움직였고 **주장의 범위만 좁아졌다.** 그런데 좁힌 쪽이 더 쓸모 있다 —
아래 결과 3 이 그 이유다.

뒤 둘은 §A 가 말로 적어 둔 "갈리는 축은 셀이냐 선이냐가 아니라 순서를 남기느냐"를
숫자로 바꾼 것이다. 그 정리는 가설이었고, 여기서 처음 잰다.

### 왜 "순서" 가 아니라 "인접 구조" 인가

지표는 재구성한 사슬과 정답 사슬이 **이웃으로 묶은 쌍**이 얼마나 겹치나다. 두 군데서
시간 순서와 갈린다.

```python
truth_pairs = {frozenset(p) for p in pairwise(truth_chain)}   # A→B 와 B→A 가 같다
```

1. `frozenset` 이라 **방향을 안 본다.** 경로를 통째로 뒤집어 재구성해도 1.0 이다.
2. 정답 사슬 자체가 **재방문을 지운 서로 다른 칸의 목록**이다. 같은 칸을 두 번 지난
   사실이 정답에서 이미 사라졌다.

그래서 이 값은 시간적 방문 순서가 아니라 경로 topology 를 잰다.

### A 를 "산책당 폴리라인 하나"로 접지 않는다

산책 하나를 선 하나로 만들면 pause·gap·jump 로 끊긴 자리가 선으로 이어지고, 그것은
세션 연속성 문서 §7(PR #83, 병합 전)이 금지한 바로 그 오류다 — 관측하지 않은 이동을
지어낸다. **chain 마다 따로 단순화**하고 chain 경계를 보존한다. 같은 규칙을 붓 쪽에서
잰 것이 `tests/territory/test_multichain_paint.py`(PR #85, 병합 전)다.

## 결과 1 — §A 의 추정은 14배 틀렸다

| 허용오차 | 점/산책 | 지터 없으면 | support 오차 | 연 스칼라 |
|---:|---:|---:|---:|---:|
| 2m | **1,168** | 23 | 0.0% | 2,336,000 |
| 5m | 982 | 15 | 0.0% | 1,964,000 |
| 10m | 627 | 9 | 0.6% | 1,254,000 |
| 20m | 163 | 7 | 3.7% | 326,000 |

§A 는 ~80점이라고 적었다. 실제는 2m 허용오차에서 **1,168점**이다. 20m 까지 열어야 163점이
되는데, 그때는 칠해진 칸 집합이 3.7% 어긋난다.

**왜 안 줄어드는지가 이 표의 핵심이다.** 세 번째 열은 같은 경로에서 GPS 지터만 뺀 뒤
같은 허용오차로 단순화한 결과다. 2m 에서 1,168 대 **23**. 경로가 복잡해서 못 줄이는 것이
아니라, **지터가 만든 지그재그를 Douglas-Peucker 가 지형으로 착각해서** 못 줄인다.

이건 A 후보를 죽이는 숫자가 아니라 **A 를 쓰려면 지터를 먼저 다뤄야 한다**는 조건이다.
평활·맵매칭 없이 원시 fix 에 단순화만 걸면 저장량의 98%가 잡음이다.

## 결과 2 — 셀 맵은 추정과 비슷하지만 산책당 158칸

산책 한 번이 칠하는 칸은 중앙 **158.5칸**, chain 은 1개.

| | 칸당 스칼라 | 연 스칼라 |
|---|---:|---:|
| B. 시각 포함 | 4 (물감·세기·첫·마지막) | 634,000 |
| C. 집계만 | 2 (물감·세기) | 317,000 |

§A 의 "~200행" 은 이쪽은 대체로 맞았다. A 와 비교하면 **2m 궤적의 1/4 ~ 1/7**.

### B 는 아직 "재 본 구현" 이 아니다

두 가지가 겹쳐 있다.

**하나.** `Cellophane` 은 `occupancy` 와 `peak` 만 들고 있고 **칸별 시각이 없다.** B 를 재려면
측정 스크립트가 `first_seen_cells()` 로 따로 만들어야 했다. 즉 B 는 "같은 것에 열 두 개
더하기"가 아니라 **칠하기 단계를 바꾸는 것**이다.

**둘.** 그 `first_seen_cells()` 도 완전한 B 가 아니다. 관측점이 **떨어진** 중심 칸만 시각을
받고, 붓이 번져서 칠한 주변 칸은 못 받는다. 진짜 B 라면 칠해진 158칸 **전부**가 first/last 를
가져야 한다.

그래서 위의 634,000 은 **표현 안(proposal)의 비용 견적**이지 구현을 잰 값이 아니다.
집 노출(결과 4)은 시작 칸 하나만 쓰므로 이 근사로 충분하고, 저장량 쪽은 그렇지 않다.

## 결과 3 — 시간 순서는 지워지지만 경로 topology 는 일부 남는다

C(집계만)의 칸 집합에서 최근접 이웃으로 사슬을 만들고, 정답 사슬과 인접 쌍이 얼마나
겹치는지 봤다. 시작점을 둘로 나눠 잰다 — 아무 정보도 안 쓰는 쪽과, C 가 **실제로 들고
있는** `occupancy` 를 쓰는 쪽.

| 시작점 | 인접 일치 | 치우침 |
|---|---:|---:|
| 무작위 순서(기준선) | 1.2% | — |
| 사전순 최소 칸 | **22.1%** | 0.97 |
| 물감 최대 칸 | **20.5%** | 0.53 |

**우연의 17~18배다.** §A 는 C 를 "순서가 사라진다"로 적었는데, 사라지는 것은 **시간 순서**고
**공간 인접 구조는 1/5쯤 남는다.** 왕복 경로에서는 공간 배치 자체가 경로의 형태라서다.

### 더 똑똑한 시작점이 더 나쁘다

리뷰에서 나온 예상은 "물감 최대 칸에서 출발하면 더 많이 복원될 것" 이었다. 실제로 재니
**약간 낮다**(20.5% 대 22.1%). 세 번째 열이 이유다.

치우침은 칠해진 영역의 무게중심에서 시작점까지의 거리를 가장 먼 칸까지의 거리로 나눈
값이다 — 1 이면 가장자리, 0 이면 한복판. 사전순 최소 칸은 **0.97 로 영역의 끝**이고, 물감
최대 칸은 **0.53 으로 한복판**이다. 최근접 이웃 사슬은 끝에서 출발하면 영역을 한 번에
훑지만, 한복판에서 출발하면 한쪽을 훑고 되돌아와야 해서 인접 쌍을 그만큼 깨먹는다.

(치우침을 **경로의 시간적 끝점**까지의 거리로 먼저 쟀다가 틀렸다. 이 산책들은 왕복이라
처음과 마지막이 둘 다 집이고, 공간적 가장자리인 반환점과 다른 자리다.)

**그래서 22.1% 를 "C 의 정확한 민감도" 로 읽으면 안 된다.** 여기 쓴 복원기는 둘 다 단순한
최근접 이웃이다. 이 숫자가 말하는 것은 **적어도 이만큼의 topology 는 샌다** 이지, 이것이
상한이라는 뜻이 아니다.

## 결과 4 — 집은 A·B 에서 10m, C 에서 220m

산책 **한 번**의 형태만으로 집을 얼마나 정확히 찍을 수 있나. 후보마다 쓸 수 있는 방법이
다르므로 방법도 다르게 잡았다.

| | 방법 | 집까지 중앙 |
|---|---|---:|
| A. 궤적 | 첫 점 | **10.3m** |
| B. 셀맵+시각 | 가장 이른 칸 | **12.4m** |
| C. 집계만 | 물감 최대 칸 | **220.4m** |

A 와 B 는 사실상 같다 — 시각이 있으면 "가장 이른 것"이 곧 출발지고, 셀 격자(11.9m)를
거치는 만큼만 흐려진다. **2m 차이는 프라이버시 차이가 아니다.**

C 는 22배 멀다. 다만 이 220m 를 "집이 안 드러난다"로 읽으면 안 된다. 앞선
[붓 감쇠 측정](2026-08-26-brush-falloff.md)이 이미 보여준 것이 있다 — **산책을 여러 장
겹치면 빈도 최대 칸이 집을 12m 안으로 찍는다.** 여기 220m 는 **한 장**일 때의 값이다.

**즉 C 가 지우는 것은 "집이 어디냐"가 아니라 "이번 산책이 언제 어디서 시작했냐"다.**

## 정리 — "민감도" 는 한 축이 아니었다

| | 연 스칼라 | 재투영 | 시간 순서 | topology | 집(1회) |
|---|---:|---|---|---:|---:|
| A. 단순화 궤적 2m | 2,336,000 | 완전 | 그대로 | 그대로 | 10.3m |
| A. 단순화 궤적 20m | 326,000 | support 3.7% 오차 | 그대로 | 그대로 | 10.3m |
| B. 셀 맵 + 시각 | 634,000 | 셀 크기에 갇힘 | 그대로 | 그대로 | 12.4m |
| C. 셀 맵, 집계만 | 317,000 | 셀 크기에 갇힘 | **버림** | 22.1% 이상 | 220.4m |

> **2026-08-26 정정 (결정 #69).** 이 표의 **B 행 "시간 순서 그대로 · topology 그대로" 는
> 과장이다.** 칸별 `first`·`last` 로는 `A→B→A→B→A` 와 `A→B→A` 를 구별하지 못한다 — 시간
> 순서의 일부지 전부가 아니고, topology 는 B 로 아예 안 쟀다. 잰 값(크기·집 노출)은 그대로다.
> 본문은 스냅샷이라 현재형으로 고쳐 쓰지 않고, 바로잡은 표는
> [결정 #69](../decisions/2026-08-26-walk-permanent-spatial-form.md) 에 있다.

§A 의 정리("갈리는 축은 순서를 남기느냐")는 **방향은 맞고 이분법이 틀렸다.** 지표 이름을
좁히고 나니 "순서" 하나가 서로 다른 축 다섯으로 갈라진다.

    시간          언제 거기 있었나                A·B 보존, C 버림
    방향          어느 쪽으로 갔나                A·B 보존, C 버림 (이 측정으로는 확인 못 함)
    topology      어느 칸이 어느 칸 옆이었나      셋 다 상당 부분 보존
    공간 위치     이번 산책이 어디서 시작했나     A 10m · B 12m · C 220m
    누적 식별성   여러 장을 겹치면 집이 나오나    셋 다 12m

마지막 줄이 중요하다. **한 장 기준으로 C 가 집을 220m 로 흐리는 것과, 여러 장을 겹치면
셋 다 12m 로 수렴하는 것은 서로 모순이 아니다.** C 가 지우는 것은 "집이 어디냐" 가 아니라
"이번 산책이 언제 어디서 시작했냐" 다.

새로 드러난 축은 **지터**다. A 의 저장량은 경로가 아니라 GPS 잡음이 정한다 — 이 축은
§A 표에 아예 없었다.

## 이 측정이 답하지 않는 것

- **어느 것을 고를지.** 여기는 숫자만이다. 고르는 것은 결정 문서에서 하고, 그때는 이
  숫자 말고도 #57(보관 기간)·#58(식별자)가 같이 걸린다.
- **평활·맵매칭을 하면 A 가 어디까지 줄어드나.** "지터 없으면 23점" 은 지터를 **완전히**
  제거한 이상적 상한이지 실제 평활의 결과가 아니다. 실제 알고리즘은 그 사이 어딘가다.
- **여러 장을 겹쳤을 때의 집 노출.** 한 장 기준만 쟀다. 겹치기는 붓 감쇠 측정 쪽에 있고,
  거기서는 셋 다 12m 로 수렴한다.
- **실기기 지터 분포.** σ=8m 은 가정이다. 결과 1 이 통째로 이 가정 위에 있다 —
  실기기가 더 조용하면 A 의 저장량은 이 표보다 작다.
- **B 의 코드 변경 비용.** `Cellophane` 에 칸별 시각을 넣는 변경의 크기는 안 쟀다.
  칠해진 **모든** 칸에 first/last 를 붙이는 완전한 B 도 아직 구현이 없다.
- **A 의 물감·세기 오차.** 재투영은 support(칠해진 칸 집합)만 봤다. 같은 칸이 칠해졌어도
  물감량이 얼마나 틀어졌는지는 안 쟀고, 재도색용 Segment 의 `dt` 를 `dist / 1.2` 로
  지어내므로 지금 형태로는 잴 수도 없다. A 를 고르려면 support·occupancy·peak 셋을 봐야 한다.
- **방향이 남나.** 인접 지표가 `frozenset` 이라 방향을 못 본다. C 가 방향을 지우는지는
  이 측정으로 확인되지 않았다 — 정리 표에 적은 것은 추론이다.
- **더 센 복원기.** 22.1% 는 단순 최근접 이웃의 값이다. 이것은 **하한**이지 상한이 아니다.
- **bytes.** 모든 크기는 스칼라 개수다. 행 오버헤드·인덱스·타입 폭·`walk_id` FK·기하 인코딩이
  전부 빠져 있어서, 실제 저장 크기 비교는 스키마 후보가 정해진 뒤에야 가능하다.
