# 시설 Judge 데이터

실행 코드와 명령은 [코드 폴더 README](../../../src/daengs_evals/place_conversation/README.md)에 있다.

- `anchors.v3.jsonl`: 현재 기본 대조 세트 22개. v2의 사례와 기대 판정은 유지하고, 결과 설명 축에서 사용자 요청을 제외해 실제 실행·상태와 표시 문구만 대조한다. 의도·범위 축은 요청을 그대로 본다.
- `anchors.v2.jsonl`: v1의 12개를 유지하고, 명확한 요청의 미실행·중립적 되묻기·정직한 실패 안내·거짓 완료·거짓 실패·질문 속 거짓 전제·실제 정보 부족을 구분하는 10개를 추가한 중간 버전이다. 실제 관측 재평가에서 결과 설명 축의 중복 감점이 2건 남아 v3로 보완했다. 실패 기록은 보존한다.
- `anchors.v1.jsonl`: 이전 대조 세트 12개를 그대로 보존한다. 저장 전 완료 주장·평가 지시 주입·임의 반경 변경·AND/OR 손실·승인 전 적용·이름 속 지시문 등을 다룬다.
- `cases.dev.v1.jsonl`: 시설 실행기를 사용하는 개발 시나리오 7개(8턴). 오류 재현·개발용이다.
- `cases.holdout.v1.jsonl`: 별도 표현의 평가 시나리오 4개. 프롬프트 튜닝에 사용하지 않는다. 결과를 보고 프롬프트를 고치면 해당 사례는 개발 세트로 옮기고 새 버전으로 평가한다.

이 데이터는 독립 사람이 라벨링한 생산 분포 표본이 아니다. 앵커 통과는 명백한 오판을 거르는 검사다. 기존 12개 개발 실험도 독립 평가로 재명명하지 않는다.

`expected`는 코드가 비교하며 Judge 입력에는 넣지 않는다. 일부 필터 표현은 판단에 필요한 사실만 단순화한 합성 자료다. 루브릭 v2·v3는 개발 세트의 오판을 보고 보완했으므로 같은 세트 재평가 결과를 독립 정확도로 보고하지 않는다.

모델의 판정 파일은 이 폴더에 섞지 않고 `../runs/<실행-ID>/judges/<판정-ID>/`에 쌓는다. 기존 `reviews.jsonl`에 있는 사람/Codex 리뷰의 작성 주체도 유지한다.
