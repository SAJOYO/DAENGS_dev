# 시설 대화 정책 구현·재평가 — 2026-09-10

관련 PR: [#412 출력 연구](https://github.com/SAJOYO/DAENGS_dev/pull/412), [#417 구현](https://github.com/SAJOYO/DAENGS_dev/pull/417). 구조와 계약은 [conversation-policy.md](conversation-policy.md)에 정리했다.

## 구현한 경계

모델의 뜻 해석과 동의 판별을 실행 권한에서 분리했다. 서버가 검증한 전체 필터 후보를 저장하고, 명확한 동의 때 같은 후보를 적용한다. 질문·모순·지역 이동에는 필터를 적용하지 않는다. 주차 true/false/null, 미지원 속성, 실제 선택 근거는 서버가 구별해 답변을 렌더링한다. 앱 UI는 변경하지 않았다.

## 평가 중 발견하고 수정한 문제

원래 실패 사례 7개를 먼저 실행한 결과 8개 대화 턴과 별도 사실 응답 1개가 통과했다. 이후 기존 코퍼스에서 부족했던 확인 후속 발화 10개를 추가했고, 19개 턴 가운데 작업 완료 기준 5개가 실패했다. 자동 검사만으로는 4개 실패였으며, 잘못된 조건을 정확하게 되묻는 문제를 수동 검토가 추가로 잡았다.

| 관측 | 실제 문제 | 보완 |
| --- | --- | --- |
| P05 | ‘선택한 이 카페 주차 가능해?’를 accept로 분류하고 저장된 필터 적용 | accept 라벨만으로 실행하지 않음. 명확한 동의 표현인지 제한하고 장소 설명은 별도 처리 |
| P06 | 대기 제안 없는 ‘응’을 show로 해석 | 제안 없는 짧은 동의는 서버가 무실행 처리 |
| P09 | 주차 해제에 alternatives=[]도 생성해 음식점 전용 OR 조건 삭제 | 속성 변경과 OR 전체 교체의 충돌 차단, 분기 내 속성 변경은 서버가 담당 |
| P10 수정 턴 | ‘주차 없어도 돼’를 주차 불가 필수로 해석 | 필수 해제·선호 전환과 주차 불가 요구를 구별하도록 의미 해석 지침 보완 |
| P10 동의 턴 | 잘못 제안한 주차 불가 조건을 정확하게 재생 | 재생 정확도와 원 요청 충족을 별개로 평가. 앞선 수정 턴의 해석부터 수정 |

보완 후 실패한 4개 사례를 3회씩 다시 실행해 24개 대화 턴에서 상태 검사와 요청 의미 검토가 모두 통과했다. 이 결과는 유한한 사례에서의 관측이며 모든 한국어 발화의 정확성을 보장하지 않는다. 특히 긴 자유 형식 동의는 다시 확인할 수 있고, 복잡한 OR와 속성 동시 변경은 명확히 나눠 요청해야 할 수 있다.

## 테스트와 경계

- 대화 정책·컴파일·사실 렌더링·HTTP/CAS 회귀 **46개 통과**. 새 테스트에는 동의 중 만료, 외부 소유자의 수락, 늦은 동의보다 새 수동 조작이 우선하는 경합이 포함된다. 최종 평가기 수정 뒤 해당 파일 10개 테스트도 통과했다(기존 9개와 새 독립 검색 사례 1개, 중복 제외 총 **47개**).
- 수정한 Python 파일의 Ruff 검사 통과. 전체 pytest는 실행하지 않았다.
- `uv run --no-sync check`: 마이그레이션 이름과 짝·단언·등록 검사 통과. Windows 바이트 검사는 이 PC의 PowerShell 스크립트 실행 금지로 실패했다. 실행 정책은 변경하지 않았다. 호출 환경의 UTF-8/cp949 출력 차이로 읽기 스레드 경고도 함께 발생했다.
- GitHub [backend tests 실행](https://github.com/SAJOYO/DAENGS_dev/actions/runs/34449739744)은 계정 결제 실패 또는 지출 한도 문제라는 annotation과 함께 작업 시작 전에 차단되었다. CI를 수동 재실행하지 않았다.
- [불투명 ID 진단](../../backend/evals/place_conversation/runs/20260910T072254Z-c0f526b-a4d72fbd89/policy-evidence-probes.json)은 같은 이름·ID의 주차 true/false/null을 다르게 설명하고 자유 문장 생성 대역을 호출하지 않았다. 모델 품질 점수와 별개의 결정론적 경계 검사다.
- 실제 Redis, PostgreSQL 공간 SQL, Android 기기 동작은 이번 합성/HTTP 평가가 증명하지 않는다. 배포·머지는 하지 않았다.

과거 #412 기준선과 새 결과는 같은 원본 사례로 비교하되, 실제 모델 호출 수와 답변 생성 방식이 다르다. 기존 자유 문장 답변을 서버 렌더링으로 바꿨으므로 ‘답변 LLM 성능 개선’이라고 해석하지 않는다. 잘못된 사실을 만들 수 있는 출력 경로를 줄인 구조 변경의 결과다.
