PR #544 를 열기 전 한 세션의 검색·판단. 가격·순위·버전은 **2026-09-15 기준**이고 빨리 낡는다.
**여기 숫자는 전부 제작사·제3자가 적은 값이다 — 우리가 잰 것은 없다**(FLUX.2-klein-4B 를 HF Space 에서 사용자가
몇 번 돌려 본 것만 예외: "닮음은 괜찮고 1024 에서 작은 글씨가 깨짐").
09-13 조사는 `research-2026-09-13.md`.

## 5. 실행 자리 — 왜 Cloud Run GPU 서비스인가

| 사실 | 출처 |
| --- | --- |
| VM `daengs` 는 e2-standard-4 — E2 는 GPU 를 못 붙인다 | 메모리(09-01) |
| Cloud Run GPU 는 서울에 없다. L4 는 싱가포르 등, RTX PRO 6000(96GB, 최소 20 CPU·80GiB)도 싱가포르 | Cloud Run 문서 |
| L4 쿼터는 리전 첫 GPU 리소스 때 3장 자동 할당 | **실측** (runbook §6, 코퍼스 잡) |
| L4 잡 11분(8vCPU/32Gi) 약 ₩250 → 시간당 약 ₩1,400, 크레딧에서 나감 | **실측** (runbook §6) |
| Cloud Run 잡 `--task-timeout` 상한 1h | **실측** (runbook §6) |
| GPU 서비스도 0대로 내려간다. 단 **인스턴스 기반 과금 필수** — 떠 있는 동안(요청 뒤 유휴 포함) 전부 과금 | Cloud Run 문서 |
| min 1 대면 L4 24시간 — 월 약 ₩100만 | 위 실측 단가 환산 |
| Compute Engine GPU 쿼터는 기본 0 (신청 필요) | GCP 문서·포럼 |
| 서울 존: G2(L4) a·b, A2(A100 40GB) b | Compute Engine 존 문서 |
| 컨테이너 파일 시스템은 메모리 — 큰 가중치는 Cloud Storage(마운트 또는 복사) 권장 | Cloud Run GPU 모범 사례 |

사용자 결정 흐름(09-15): 비교 테스트 → job 을 권했으나 "카드 생성은 결국 backend 가 부르는 service 모양" 이라는
지적으로 **service** · RunPod 대신 **GCP 크레딧** · ComfyUI 대신 **diffusers** · 생성 로직 패키지와 **분리한 새 패키지**.
