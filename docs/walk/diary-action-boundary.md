# 행동 핀 생성 경계와 독립 메모

2026-09-14, DEV #527. `018a9ce7` 기준의 실제 카드 작성 경로를 수정한다.
브랜치 구현과 배포 여부는 구별한다. 이 문서는 #508의 행동 생성 범위와 제목 의존성을 대체한다.

후속 [보호자 시점 연결](diary-narration.md)에서도 이 행동 핀·독립 메모 경계를 유지한다.
공간에는 실제 동행과 함께 산책한 큰 상황을 허용한다. 이 공통 시점은 행동 핀을 대신하거나
구체적인 이동·정지·반려견 행동을 생성할 근거가 아니다. 현재 v7 저장본에도 아래 검증을 적용한다.

## 결정과 이유

동선 분석이 풍부해도 그것이 새 행동 문장을 만들라는 제품 규칙은 아니다.
#508은 `행동 핀 OR 이동 재료`로 작성 범위를 넓혀, 메모·사진·경로 장면에도 이동 일지를 만들었다.
이를 **유효한 행동 핀**으로 복구한다. 공간 작성기와 행동 작성기는 계속 분리한다.

| 입력 | action 작업 | 전달 내용 |
| --- | --- | --- |
| 핀 없음, 이동 있음/없음 | 없음 | 없음 |
| 메모·사진, 이동 있음 | 없음 | 원문은 독립 보존, 공간 보충만 가능 |
| 행동 핀, 연결 가능한 이동 없음 | 1개 | 기록된 행동 |
| 행동 핀, 연결 가능한 이동 있음 | 1개 | 기록된 행동 + 해당 시각의 이동 맥락 최대 1개 |

행동을 주제로 쓰고, 이동은 필요할 때 보조한다. 행동 핀은 한 시점의 기록이므로
그 주변 구간을 행동의 지속 시간·원인으로 확대하지 않는다. 출발부터 종료까지의 회전 순서를
행동 문장으로 풀어 쓰도록 입력하지 않는다.

## 코드가 지키는 경계

1. `action_anchor`는 삭제되지 않은 행동 기록만 반환한다. `action_job`은 핀이 없으면 즉시 끝낸다.
2. 작업 생성·정규화·응답 채택 모두 `require_action`으로 핀을 요구한다.
3. 조립 시 `require_scene_action`으로 카드·기록 ID·시각·행동 종류·대상을 다시 맞춘다.
4. 캐시는 현재 정책과 실제 정규화 입력이 같을 때만 재사용한다. 이동만 있는 과거 작업을
   새 생성에 붙이지 않는다. 잘못된 입력은 캐시보다 먼저 거절한다.
5. 새 v6 저장 영수증도 같은 핀과 메모 제외 제목 의존성을 검증한다.

과거 저장본의 해시·본문은 당시 계약대로 읽는다. 이미 발행된 일기를 새 규칙으로 자동
재생성하거나 수정하지 않는다. DB 스키마나 공개 응답 형식 변경은 없다.
레거시 슬롯 작성기는 새 이동 형식을 독립 장면 서술 재료로 소비하지 않는다.

## 이동 분석과 소비를 나눈다

원래 스탬프에는 모든 phase·근거·지지 구간을 그대로 보관한다.
`pin_movement`는 그중 핀 시각이 `[start, end)`에 속하는 phase만 요청으로 복사한다.
회전 등 순간 사건은 실제 사건 시각이 핀 시각과 같은 경우만 포함한다.
겹치는 phase가 여러 개이거나 연결이 없으면 가까운 것을 대신 붙이지 않고 행동만 쓴다.

동시에 성립한 경로 형태·되짚기·속도는 코드에서 하나의 `movement_context`로 합친다.
서로 상충하는 형태나 속도는 맥락을 생략한다. 단순 직선보다 함께 성립한 구체 형태를 우선한다.
LLM이 여러 단계 중 골라 관계를 추론하게 하지 않는다.

```json
{
  "recorded_action": {"id": "a1", "actor": "보리", "action": "냄새 맡기"},
  "movement_context": {
    "id": "m1",
    "meaning": "대체로 곧게 이동. 그 시각의 걸음은 이번 산책의 다른 이동 구간보다 상대적으로 느린 걸음",
    "relation": "행동이 기록된 시각의 산책 이동. 행동의 지속 구간이나 원인은 아님"
  }
}
```

입력에는 초·속도 수치·임계값·해시·진단 배열이 없다. `m1`은 동시 근거들의 내부 ID로
복원하며 인용하지 않았다면 사용 근거로 저장하지 않는다. `a1` 인용은 필수다.
이동이 없으면 기존 행동 전용 입력을 사용한다. 생성 실패 시 기록된 행동의 기본 문구만 남긴다.
프롬프트는 행동 중심 한 문장과 선택적 맥락을 안내한다. 인용 검사는 문장 의미의 정확성까지
보장하지 않으므로 이번 오프라인 확인을 Gemini 서술 품질 평가라고 부르지 않는다.

상대 저속 `<0.5배`, 상대 고속 `>1.5배`, 연속 `10초 이상`은 그대로다.
보통 속도를 매번 재료로 만들지 않고, 드문 고속을 억지로 만들지 않는다.
분류에 필요한 시간과 수치는 내부 조건으로만 사용한다.

## 메모·제목·공간

메모는 `writing.original_text`에 공백·개행까지 보존한다. 공간·행동 요청에도,
마지막 제목 요청에도 보내지 않는다. 제목은 공간·행동의 확정 생성 부분과 표시되는 관측을
시간순으로 읽는다. `title_context`와 `title_revision`에는 원문이 없다.
메모 텍스트와 그 버전만 바뀌면 작성 요청과 제목 요청은 같아 캐시를 재사용한다.
위치·시각·행동 등 실제 생성 의존성이 바뀌는 경우와 구별한다.

기존 API 호환용 `body`는 표시용 조립 결과로 유지한다. 생성 입력을 이 문자열에서 역으로
만들지 않는다. 이 PR은 APP 화면을 바꾼 작업이 아니다.

공원은 정규화 단계에서 고유명·종류·거리 수치를 제외하고 ‘근처에 공원이 있음’으로 준다.
등록 지점은 방문·내부 진입을 보장하지 않는다. 주소는 기존 동 표기를 유지한다.
피복·공원을 설명할 때 좌표/조회/등록/분류 보고서 문체를 쓰지 않도록 공간 프롬프트를 정리했다.

## 버전과 확인

- 모델 입력: `diary-prose-input-v6`
- 작성 정책: `shared-orchestration-card-writing-v7`
- 공개 보드·narrative 형식·발행 마감·모델·동시성은 기존 계약 유지
- 신규 문장 생성, 과거 저장본 판독, 과거 실험 재현을 분리

양재 `public-02`의 저장 공공자료와 가상 GPS를 그대로 재생했다. 외부 호출은 0회다.

저장 후 재조회가 일치했고 실제 정규화 요청에서 두 메모가 모두 제외됐다.
