# 공간 일괄 공급과 선택적 상세 조회의 실제 서술 비교

2026-09-14, DEV #520 후속 4단계. 기준 서비스 커밋 `c3d08c96`.

## 판단

선택적 상세 조회는 실제 Gemini에서 동작했다. 그러나 이번 세 장면에서는 서술 품질의
개선을 확인하지 못했다. 모델에 상세를 골라 받게 하는 것과, 받은 근거를 과장 없이
자연스럽게 쓰는 것은 서로 다른 문제였다.

새 방식은 공원만 조회하고 상권 상세를 받지 않았다. 기존 방식도 최종 문장에서는
같은 공원·동·피복만 인용했다. 따라서 이번 표본은 도구의 선택 동작을 보여주지만,
기존보다 더 좋은 재료 선택을 했다는 증거는 아니다.

## 비교 조건

- `public-02`의 저장된 실제 공공자료를 공통 준비·정규화 함수로 다시 읽었다.
  GPS·행동·메모는 합성 산책 시나리오이며 실기기 기록이 아니다.
- 결과를 보기 전에 배경 유형이 다른 1·2·3번 장면(풀밭·길·숲)을 선택했다.
  가용 재료는 각 장면에 동·피복·지역 기온·주변 공원·광역 상권의 5개다.
- 모델은 양쪽 모두 `gemini-3.1-flash-lite`, temperature 0, 응답 상한 512토큰이다.
  각 방식에 전체 15초를 주었다. 실제 발행 경로의 시간 예산을 측정한 실험은 아니다.
- 기존 방식은 `5cbe89b2`의 단일 요청 설정을 비교 도구 안에서 재현했다.
  정규화한 5개 재료와 기존 공간 프롬프트·JSON 스키마를 한 번에 공급했다.
- 새 방식은 현재 `writing/provider.py`의 `generate_card_prose`를 직접 호출했다.
  기본 3개와 상세 후보의 ID·주제를 먼저 받고, 선택한 상세만 내부 도구로 반환했다.
- 새 방식에는 도구 선언·짧은 사용 지침이 추가되고 첫 응답 형식도 다르다.
  공급 방식 하나만 독립적으로 바꾼 실험으로 해석하지 않는다.
- 1단계에서 작성한 서술 예시는 프롬프트에 추가하지 않았다. 이번 실행 중 프롬프트나
  서비스 코드를 조정하지 않았고, 답변을 고쳐 쓰거나 재추첨하지 않았다.

추가 공공 API·행동·제목 작성·DB·발행은 실행하지 않았다.

행동 작성 작업을 열지 않는 코드 경계와, 공간 작성기가 행동 표현을 생성하지 않는 것은
같지 않다. 이번에는 행동 작성기를 한 번도 호출하지 않았지만 공간 응답 자체에 이동
표현이 들어왔다. 현재 인용 검사는 실제 공급한 ID인지 확인한다. ID가 맞더라도 문장이
근거의 관계를 과장했는지까지 판정하지 않는다. **응답 계약 통과는 서술 품질 통과가 아니다.**
