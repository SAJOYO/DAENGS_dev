# 공통 필터 편집 Gemini 실호출 평가

2026-09-09, DAENGS_dev #362 후속 검증. 모델은 `gemini-3.1-flash-lite`,
Interactions API, temperature 0, store=false, 호출 제한 30초다.
합성 상태·문장 → 실제 Gemini → production proposer → production compiler까지 확인했다.
장소 DB, 운영 Redis, 로그인 앱 HTTP와 실제 검색 결과는 이번 평가에 포함하지 않았다.

## 실호출에서 발견한 문제와 수정

1. 전체 `EditProposal.model_json_schema()`로는 HTTP 400이었다. 같은 키·모델로 최소 요청과
   작은 스키마는 성공했다. 참조만 펼친 버전도 400이었고, 참조를 펼치고 설명·기본값·길이·개수·수치
   경계를 생략한 전송용 스키마는 성공했다. 특정 JSON Schema 키워드 하나가 원인이라고
   단정할 만큼 분리 실험하지는 않았다. 공개 계약과 서버 Pydantic/컴파일 검증은 유지했다.
2. 스키마 수정 후 첫 15개 모델 응답 중 7개가 `invalid_evidence`로 막혔다. 한글 인용문이
   맞아도 모델이 위치를 잘못 계산했다. 이제 정확한 인용문이 원문에 한 번만 있으면 서버가
   위치를 계산한다. 텍스트를 고치거나 여러 등장 위치 중 하나를 추측하지 않는다.
3. `주차 가능하고 반려동물 전용인 곳만`이 두 OR 분기로 나뉘었다.
   `주차 필수 + (카페 OR 전용 음식점)`에서는 전용 조건이 카페에도 적용됐다.
   공통 AND, OR 대안, 대안 내부 AND와 수식 범위를 프롬프트에 명시했다.
4. 다음 20문장 평가에서 `주차 상관없어`는 삭제 대상 ID와 객체를 함께 출력했고,
   장소명 해제는 빈 문자열 대신 null을 출력했다. 모두 `edit_payload_mismatch`로 차단됐다.
   연산별 단일 payload와 이름 해제의 빈 문자열 규칙을 명시했다. 잘못된 응답을 임의로
   제거·변환해서 통과시키지 않는다.

## 판정 기준과 기록

- 주차/전용/업종 논리식은 카페·음식점 × 주차 true/false × 전용 true/false의 8개 경우에
  대해 기대 논리식과 비교한다. 모델이 생성한 ID나 분기 순서가 달라도 같은 의미면 통과다.
- 조건 유지, 주차 해제, 장소명 해제, 주차 선호는 각 상태의 보존·변경을 검사한다.
  위치·반려견·미상 정책·결과 상한이 바뀌면 실패다.
- 미지원 요구는 `unresolved`가 있고 `proposed_state=null`이어야 통과다.
  지원되는 조건만 실행하고 나머지를 누락하는 응답은 통과시키지 않는다.
- 업종·이름 변경에 대한 서버 확인 절차는 유지한다. 올바른 변경안이 확인 대상으로
  반환되는 것도 해석 성공으로 센다. 통과 수가 자동 적용 수를 의미하지 않는다.
- JSONL은 평가 당시 응답과 결과다. 중복인 `compiled.base_state`와 `compiled.proposal`만
  생략했으며 각각 최상위 필드에 남아 있다. `proposal`은 provider의 검증과 근거 위치
  보정 **후** 값이다. 보정 전 모델 인용 위치 전체를 수집한 자료는 아니다.

| 실행 | 결과 | 기록 |
| --- | --- | --- |
| 스키마 보완 직후 | 15개 모델 응답 중 8 통과, 7 근거 오류. 16번째는 HTTP 429로 중단 | [baseline](2026-09-09-baseline.jsonl) |
| 근거 보정·AND/OR 지시 보완 후 | 20개 중 18 통과, 삭제 payload 오류 2개 | [revised](2026-09-09-revised.jsonl) |
| 삭제 payload 지시 보완 후 | 기존 20/20, 새 표현 8/8 통과 | [final](2026-09-09-final.jsonl) |

최종 28회는 모두 HTTP·형식·컴파일·의미 판정을 통과했다. 호출과 컴파일을 합친 지연은
중앙값 3.64초, 최소 1.80초, 최대 7.22초였다(호출 사이 5초 대기 제외).
`주차 상관없어`와 단순 주차 해제는 확인 없이 해제되고, 업종 변경·장소명 해제는
기존 서버 정책대로 확인 대상으로 반환된 것을 응답에서도 확인했다.

실험별 시작 시각·모델·집계와 최종 provider 소스의 LF 기준 SHA-256은
[summary](2026-09-09-summary.json)에 기록한다. 429는 해석 실패율과 구분한다.
첫 실행에서 확인된 무료 계정의 분당 15회 한도를 고려해 후속 실행은 호출 완료 뒤
5초 간격을 두었고, 실패 자동 재시도는 하지 않았다.

## 재현

`backend/`에서 다음을 실행한다. 외부 환경 파일은 `GEMINI_API_KEY=...` 또는
`GEMINI: ...` 한 항목만 추출하며 다른 DB·인증 설정을 프로세스에 로드하지 않는다.
키를 저장소에 복사하거나 명령행 값으로 넘기지 않는다. 출력 경로는 새 파일이어야 한다.

```powershell
uv run --no-sync python tools/eval_place_filter_edits_20260909.py --env-file C:/external/.env --output evals/place_filter_edits/new-run.json --limit 28
```

이 스크립트는 이번 28문장을 재현하는 단일 파일 도구다. 실제 외부 API 호출을 한다.
자동 CI에 연결하지 않았다. CLI 인자·lint는 로컬 확인했으며 모델 평가는 같은 코드의
작업용 원본으로 실행한 뒤 경로 인자와 덮어쓰기 방지를 추가해 저장했다.

회귀 테스트는 변경된 provider, compiler, 인증 gateway에 한정했다.

```powershell
uv run --no-sync pytest tests/place/place/filters/test_edits.py tests/place/place/filters/test_proposer.py tests/test_place_filter_edits_api.py -q
```

37개 통과. 스키마를 줄여도 긴 ID·과도한 편집 수·문자열 boolean·삭제의 중복 payload·
null 이름 payload는 거절한다. 원문에 없는 인용문과 중복 인용문의 잘못된 위치도 거절한다.
정확한 위치로 지정된 중복 인용문과 한글/이모지의 단일 인용문 위치 보정은 허용한다.

## 평가의 한계

기존 20문장은 오류를 보고 프롬프트를 보완한 회귀 집합이다. 추가 8문장은 마지막 프롬프트
수정 뒤 작성해 처음 호출한 표현 변형이며, 별도 사람이 만든 독립 검증 집합은 아니다.
각 최종 문장은 한 번씩만 호출했다. 이 수치로 일반 한국어 검색 정확도나 반복 안정성을
주장할 수 없다. temperature 0도 매 호출의 동일 응답을 보장하지 않는다.

진리표는 알려진 boolean 값에 한정한다. 정보 미상 처리·모순·권한·재시도는 기존
deterministic 테스트가 다루며, 이번 실호출이 그 전체 행렬을 대체하지 않는다.
향후 확인 대상은 실제 사용자 문장, 같은 문장 반복, 오탈자·복합 정정·인용·조건부 요구,
기존 복잡한 OR 상태 편집, 운영 Redis/DB와 앱 적용까지의 왕복이다.
