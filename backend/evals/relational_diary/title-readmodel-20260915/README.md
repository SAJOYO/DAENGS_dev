# 전체 제목 readmodel — 실제 입력·출력 비교

Python 3.12, 모델 `gemini-3.1-flash-lite`. 기준 브랜치 HEAD `f599a1fa`에 제목 계약 구현을
추가한 작업본에서 실행했다. 본문 재생성 없이 이전 실험의 확정 발행본을 사용했다.

## 같은 본문, 두 입력 방식

> 매헌로의 풀밭을 지나 어느덧 강남대로의 길 위로 걸음을 옮겼고, 근처 마방 공원과의 거리도 조금 더 가까워졌다.
> 보리가 강남대로 길 위에서 냄새를 맡았다.

원본 3장면 중 공간 두 장면이 거절되어 **실제로 채택된 본문은 가운데 장면 하나**다.
거절된 후보를 되살리거나 본문을 고쳐 좋은 입력으로 바꾸지 않았다.

| 방식 | 실제 제목 | 검수 |
| --- | --- | --- |
| 기존 목록 | 매헌로와 강남대로, 마방 공원 산책 | 통과 |
| 새 readmodel | 매헌로와 강남대로를 걷는 보리 | 통과 |

기존 입력은 `scene:1` 아래 공간·행동을 합친 본문이고, 새 입력은 원래 장면 ID와 `order: 2`,
시각 및 공간·행동을 나눈 필드를 유지한다. 이번 장면에는 별도 이동 관측이 없다.
제목 작성·검수 프롬프트와 출력 스키마는 두 조건에서 동일하다. 대표 지명·제목 틀을 지정하지 않았다.

작성 2회 + 검수 2회, 총 4회 모두 반환. 응답 완료 뒤 최소 10초 간격, 호출당 15초 제한,
전체 120초 상한, 자동 재시도 없음. 새 공공 API·TMAP·본문 생성 호출은 없다.

**해석:** 새 제목은 공원 나열이 빠지고 보리가 등장했다. 한 번씩 생성한 결과로
새 입력이 더 좋은 제목을 만든다고 확정하지 않는다. 원래 채택 본문에는 근거 없는 도로 통과
표현이 있었고, 제목도 그 내용을 따른다. 이 readmodel은 채택 본문을 정확히 전달하는 계약이며
본문의 의미 오류를 다시 판정하거나 고치는 장치가 아니다.

## 구현·코드 검사

- `TitleReadModel`은 원래 장면 ID·순서·시각·채택 공간·현재 행동·연결 이동 관측을 보존한다.
- 제목 작성과 의미 검수가 같은 입력을 사용한다. 원문·미채택 후보·헤더·원자료를 제외한다.
- 로컬/DB 저장 경계와 발행본 조회가 제목 입력과 확정 본문의 일치, 후보와 최종 제목,
  검수 입력·판정의 연결을 검사한다. 기존 제목 저장본은 계속 읽는다.
- 관련 4개 코드 검사 파일 63개 통과. 검수 상태 우회 방지 추가 후 제목 파일 20개 재확인.
  숫자는 중복되므로 합산하지 않는다. 실제 DB·APP 연결을 새로 실행한 결과는 아니다.

## 원문과 재현

- `manifest.json`: 실제 프롬프트·모델·입력 발행본 digest·비교 조건.
- `calls.json`: 모든 실제 요청·응답·호출 소요 시간.
- `results.json`: 두 조건의 후보·검수·최종 결과, 새 readmodel과 연결 정보.
- `execution.json`: 호출 시작·종료·간격 및 재시도 없음 기록.
- 입력: [이전 확정 발행본](../review-consistency-20260915/receipt.json.gz).

backend에서 다음 명령으로 같은 입력 조건을 다시 실행할 수 있다. 출력 폴더는 새 경로여야 하며
실제 모델 호출이 발생한다. 호출 결과 자체의 동일성은 보장하지 않는다.

```powershell
uv run python tools/run_relational_title.py --receipt evals/relational_diary/review-consistency-20260915/receipt.json.gz --env-file <비공개-환경파일> --output <새-출력폴더> --compare-legacy
```

비교 플래그를 빼면 새 제목 작성·검수만 실행한다. 재현 도구의 기존 목록 작성은 비교용이며,
제품 오케스트레이터는 새 전용 작성기를 호출한다.
