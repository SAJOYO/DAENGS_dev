# 재편성: 문화시설이 기반, 인허가는 오버레이 — 의료는 하위로

> 데이터 층(시설 기반·MOIS 의료 오버레이)과 필드 병합 규칙은 유지한다. 제품 최상위를
> `/facility` 로 두는 phase 2는 채택하지 않았고, [결정 #65](2026-08-26-place-first-discovery.md)의
> `Place → kind 후보군 → 조건 → 사실 순서`로 대체했다.

08-24 실측의 결론. 인허가 원천만으로 병원/약국은 디렉토리 이상이 안 되고
(영업시간 0% · 과목 커버리지 0.3% · 간판 24시 정밀도 73%/재현율 47%),
견주의 실제 야간 응급 흐름은 검색엔진이 이미 이긴다 (창녕 블라인드 테스트).
반면 KCISA 반려동물 동반 문화시설 CSV(70,650행)는 카페·여행지·미용·펜션까지
운영시간·휴무일·주차·동반조건을 주고, 동물병원/약국은 그 **한 카테고리**일 뿐이다.
원천의 모양대로 제품을 놓는다.

## 층 구조

| 층 | 원천 | 역할 | 갱신 |
|---|---|---|---|
| **기반** | KCISA CSV (`facility`, source=kcisa) | 전 카테고리 존재·운영시간·동반조건 | UPSERT + prune (스냅샷 의미 유지) |
| **기반** | KTO API (`facility`, source=kto) | 관광 큐레이션 9,692곳. 안정 ID·수정시각 보유 | UPSERT + 워터마크 증분 |
| **오버레이** | MOIS API (`place`) | 의료 존재·인허가 상태의 진실. 폐업이면 기반층에 있어도 숨김 | 일 배치 (기존) |
| **링크** | `facility_link(source, source_ref)` | 이름정규화+150m. 특정 테이블 FK 아님 → 원천 N개 | 원천 교체 시 재구축 |

### 식별자
`facility.id`(BIGSERIAL)는 **외부 식별자가 아니다.** 외부(즐겨찾기·추천 이력·딥링크)가
잡을 것은 `(source, source_ref)`다. 적재는 이 쌍으로 UPSERT하므로 id는 재적재를 넘어
유지된다 — DELETE 후 INSERT였다면 매 동기화마다 바뀐다.
KTO는 `contentid`, KCISA는 안정 ID가 없어 `md5(정규화 이름 + 5자리 좌표)`로 만든다.
시설이 이전·개명하면 새 키가 되고 옛 행은 prune으로 사라진다 — 원천 한계를 그대로 받는다.

### 필드 병합 — 행 승자독식 금지
같은 시설이 두 원천에 있으면 **노출 행은 하나, 필드는 병합**한다. 존재·이름·좌표는 최신
원천이, 그 원천이 안 주는 운영시간·주차·홈페이지는 링크된 원천에서 빌린다. 빌린 값에는
`field_sources`로 원천과 기준일이 붙는다.
행 단위로 최신 원천을 택하면 KTO(목록만 보유)가 KCISA(운영시간 보유)를 가려 정보가
사라진다 — 교차 링크 847쌍 전부에서 그렇게 된다. 의료 쪽 `attach_facility_hours`가
이미 필드 단위로 고르고 있었으므로 문화 검색도 같은 철학으로 통일한다.

우선순위 규칙: 존재/영업상태는 MOIS 승, 운영시간·휴무일·주차·홈페이지는 기반층에서
빌리되 **출처와 기준일을 함께 낸다**. 세 번째 원천부터는 `o.source < n.source` 대신
명시적 우선순위 표가 필요하다 (지금은 kcisa<kto가 우연히 과거<최신과 일치).

**제품 요구의 경계**: 이 기능은 "지금 여는지 알려준다"가 아니라 **"참고 가능한 운영시간을
출처·기준일과 함께 보여준다"**이다. `open_now` 판정은 여전히 MOIS `place.hours`만
쓰고 대부분 미상으로 남는다 — 매칭 재현율 70%인 링크로 영업 판정을 하면 A병원 시간이
B병원에 붙는다.
CSV 동물약국 46,105행은 등록 동물약국(19,251)보다 많다 — MOIS 미매칭 약국 행은
의료 검색에 안 태운다 (동물의약품 판매 자격 미확인).

## 축 재배치 (phase 2 — 미구현)

- **어떤 상황인가**: 전역 '급한 상황' 토글 제거. 긴급도 판단은 응답 에이전트(RAG)로
  이관하고 우리는 그 등급을 검색 조건으로 받는다 ([에이전트 경계](2026-08-24-agent-parallel-response.md))
- **어디를 갈까**: 문화 카테고리가 메인, 의료는 하위 가지.
  `/facility/search` 가 권위, `/hospital`·`/pharmacy` 는 kind preset facade —
  facade 가 자체 정책을 갖지 않는다. 챗봇 계약(state 왕복·딥링크, 결정 #9·#19)은
  facility 표면으로 **끌어올린다**: 문화가 메인이 됐으므로 "애 데리고 갈 카페"도
  "눈이 뿌연데 갈 병원"과 같은 refine 루프를 탈 자격이 있다
- **어떻게 갈까**: 그대로 별도 정책. 노드(장소)가 뭐로 바뀌든 간선(이동) 정책은 독립 —
  journey 모듈이 이미 그 모양

## 안 하는 것 (08-23~24 대화에서 기각)

- 병원 능력(과목·실력·응급역량) 기반 개인화 — 오른쪽 항 없음, 표방은 표방으로만 표기
- 간판 24시를 단독 신호로 사용 — 4번 중 1번 거짓, 진짜의 절반 놓침. CSV 운영시간과
  교차 일치한 것만 '24시간(2025-03 기준)' 표기
- 야간 응급 검색 경쟁 — 견주+네이버가 더 빠르고 신선함
- KTO 서버측 증분(`modifiedtime` 파라미터) — 어떤 값에도 totalCount=0을 돌려준다
  (2026-08-24 실측: 20250101/20260301/20260601 전부 0, 파라미터 없으면 10,152).
  목록은 전량 받고 **적용을 증분으로** 한다
