# 시설 검색 전용 LLM Judge

시설 입력의 해석과 실행 결과를 검토하는 오프라인 평가기다. 코드는 [place_conversation](../../backend/src/daengs_evals/place_conversation/README.md)에 있으며 실행 명령과 파일 설명은 그 README가 기준이다. 데이터는 [judge 안내](../../backend/evals/place_conversation/judge/README.md)를 따른다.

## 평가할 것

| 축 | 목적 |
| --- | --- |
| `intent_alignment` | 요청 조건 누락·임의 추가·AND/OR 변경·맥락 오용 찾기 |
| `scope_fit` | 시설 요청 오거절과 범위 밖 자유답변을 모두 찾기 |
| `result_faithfulness` | 실제 실행·반환 사실과 사용자 문구가 일치하는지 확인 |

기준은 [시설 범위 정책](scope-guardrails.md)과 [응답 정책](response-policy.md)이다. 고정 강아지 문구의 귀여움은 문구를 바꿀 때 검토한다. 매 실행마다 장문·친절함을 보상하는 문체 점수를 만들지 않는다.

각 축에 현재 입력·필요한 이전 대화·실행 전후 상태·실제 반환 문구를 제공한다. 의도 축만 모델 계획도 보며, 결과 설명 축은 계획을 실행 증거로 보지 않는다. 다른 사례·반복·변형의 맥락, 정답 라벨, 코드 점수, 기존 사람/Codex 리뷰는 입력에서 제외한다.

결과는 `pass / fail / uncertain / not_applicable`와 짧은 사유·실제 입력 필드의 JSON Pointer 근거다. 자료 누락·선행 턴 실패·입력 상한 초과는 모델을 호출하지 않고 `unmeasured`로 남긴다. 관측을 임의 요약하거나 잘라서 완전한 자료인 것처럼 보이지 않는다.

## 판정 소유권

코드 검사·LLM Judge·기존 리뷰를 별도 열로 표시한다. 모델 의견이 코드 검사 실패를 지우지 않는다. 자동 판정만 존재하면 의미 평가는 `review_required`로 유지한다. 기존 `reviews.jsonl`을 모델 판정으로 채우거나 수정하지 않는다.

Judge는 검토 보조다. 앵커 검사만으로 사람과의 일치도를 확보한 것이 아니므로 종합 품질 점수나 출시 자동 승인으로 사용하지 않는다. 제공자 오류·관측 누락·보류도 통과로 세지 않는다.

## 실행과 재현

기존 시설 `runner.py`·`checks.py`·`report.py`를 확장했다. 공통 대화 Judge의 모델 핀·앵커 검사·설정·지연 API 생성 방식을 따르되 시설 전용 루브릭과 출력 계약을 사용한다. 공유 설정 이름은 `OPENAI_API_KEY`, `OPENAI_JUDGE_MODEL`, `OPENAI_TIMEOUT_S`다.

각 판정 실행은 별도 폴더에 입력·호출·결과·설정·해시를 보존한다. 모델·프롬프트·관측·앵커·평가 코드가 달라지면 새 실행이 필요하다. 동일 설정에서는 완료된 축을 제외하고 재개할 수 있다. 호출 상한은 앵커·재시도까지 포함하고, 최초 오류와 사용량을 남긴다. API SDK의 숨은 재시도는 사용하지 않는다.

기존 실행기 기본 모델도 현행 시설 설정 `FACILITY_CONVERSATION_MODEL`을 따르도록 연결했다. APP과 운영 서비스 요청 경로·DB는 변경하지 않았다.

첫 버전은 합성 검색과 서버 prepare/answer까지 관측한다. 공통 라우터·APP 실제 선택·회원 찜 저장 완료·Redis CAS·PostGIS 정확도는 별도 검증 대상이다. 추후 해당 관측 형식을 연결할 때 경계와 데이터 버전을 명시한다.

## 2026-09-12 구현 검증

시설 대화 회귀 검사 223개가 통과했고 기존 opt-in live 검사 1개는 건너뛰었다. 최종 대조 사례·리포트 변경 뒤 Judge와 평가기 타겟 검사 40개도 통과했다. Ruff, `uv run check`, CLI 도움말·사례 로딩, 문서 링크를 확인했다.

[실제 연결 시도 기록](../../backend/evals/place_conversation/runs/20260912T130753Z-670a13a-28eb2ff4c2/smoke-summary.json)은 5개 사례·6턴이다. Gemini 시설 실행 3턴의 관측을 얻었고 제공자 오류 2턴·선행 오류로 미실행 1턴을 구분했다. OpenAI Judge는 제공된 키의 HTTP 401로 앵커 단계에서 막혀 **실제 의미 판정은 0건**이다. Judge 품질이 검증됐다는 결과로 읽지 않는다.

최초 구현은 같은 인증 오류를 16회 기록했다. 이를 계기로 재시도 불가 4xx가 나오면 같은 실행의 추가 호출을 중단하도록 보완했다. 회귀 검사는 세 축의 시도 횟수가 1/0/0이 되는지 확인한다. 오류 기록은 그대로 보존했고 같은 키로 재호출하지 않았다. 당시 앵커는 8개였으며 최종 대조 세트는 12개다. 유효한 키로 새 Judge 실행을 만들어 앵커와 실제 판정을 확인하는 일이 남아 있다.
