## 실패한 S07을 남기는 이유

“찜하지 말고 주차 되는 카페만 찾아줘”의 기대는 **저장 행위만 부정하고 현재 찜 범위에서
주차 필수 검색**이었다. 모델은 주차 조건을 맞췄지만 `search_scope`를 일반 장소로 바꿨다.
지침에 이 차이를 명시해도 동일했고, 모호한 enum 이름 `search`를 `all_places`로 바꾸고
현재 집합을 별도 필드로 줘도 해결되지 않았다.

정책은 범위 복귀와 조건 변경을 부분 실행하지 않아 목록·필터·찜은 그대로 남았다.
따라서 **무변경 경계는 지켰지만 바로 검색하는 유용성 기대는 실패**다. 이 건을 통과로
바꾸거나 일반화된 정확도를 주장하지 않는다. 현재 안내는 일반 검색으로 이동하라고
단정하는 대신, 어느 집합에서 찾을지와 조건을 함께 확인하도록 수정했다.

같은 모델에 예문을 계속 덧붙여 성공 한 번을 얻는 것보다, 다음 평가에서 저장 동작의
부정과 검색 집합 변경을 대비한 문장을 늘리는 것이 필요하다. 새 모델/프롬프트/구조를
비교할 때 S07을 고정 회귀로 유지한다. 이번 수정 후 12문장 전체 재실험은 하지 않았다.

## 반복 방법

```powershell
# backend/
uv run python -m daengs_evals.place_conversation.saved_search --key-file <로컬키파일>
uv run python -m daengs_evals.place_conversation.saved_search --key-file <로컬키파일> --only S07,S08
```

입력 사본·소스 해시·원문 요청/응답·의도·컴파일 결과는 실행 폴더에 저장한다.
제공자 오류는 `incomplete`로 구분한다. 평가 도구는 관측 기록용이며 프로세스 종료 코드가
성공률 게이트는 아니다. 합성 상태의 작은 표본을 실제 회원 데이터의 종단 검증으로 보지 않는다.
