## 완료한 1~6번

2. 현재 행동의 공간 재료에 `time_meaning`을 보존해 작성과 검수까지 동일하게 전달한다. 이전 장면이나 행동을 현재 행동 입력에 섞지 않는다.
3. 순차 작성 진입점에서 전체 소스 연결 검증·복사를 수행하고, 장면별로는 계획을 검증한다. 장면 수만큼 전체 소스를 반복 검증·복사·해시하던 경로를 제거했다. 저장 경계의 독립 검증은 유지한다.
4. 장면·행동·제목의 호출 예산에 따라 전체 제한을 계산하고 HTTP 예약 만료와 맞췄다. 응답 완료 뒤 10초 간격, 429 중단, 자동 재시도 없음은 유지한다. 타임아웃 취소를 공급자가 삼켜도 늦은 후보를 채택하지 않는다. storyboard 프록시 제한은 1650초이며 실제로 그 시간만큼 기다리는 정책은 아니다.
5. 저장된 3장면·행동핀 1개로 실제 Gemini 작성·검수를 실행하고 모든 후보와 거절을 보존했다.
6. 현행 계약·실행 경로를 문서 첫머리에 정리하고 v5 문서를 역사적 기록으로 구분했다. 이번 입력·원문·검수·발행본을 이 폴더에 묶었다.

## 실제 모델 결과

`gemini-3.1-flash-lite`, 작성 5회 + 의미 검수 5회 = 총 10회.
109.8초에 모두 반환했고 로컬 `save_skeleton` → `read_skeleton` 결과가 일치했다.
10초 호출 간격과 전체 255초 제한을 사용했다. 새 공공 API·GPS·TMAP 호출이나 프롬프트 덮어쓰기는 없었다.
입력은 기존 공공 공간 자료로 만든 간이 장면이며, 장면 사이 경로 연결과 정지·속도·동선 모양 근거는 없다.
따라서 이번 실행으로 이동 재료의 효과를 검증했다고 해석하면 안 된다.

그런데 검수는 모든 항목을 true로 반환했다. 공간 1·3의 유사한 범위 확대는 거절했다.
검수는 규칙 검사만이 아니라 모델 판단을 하고 있지만, 그 판단이 일관적이지 않다.
최종 공간 본문이 한 장만 남은 것을 품질 개선 성공으로 세지 않는다.

실행 구조는 후보 1회 작성 후 같은 모델로 1회 검수하는 방식이다. 거절된 후보를 반복 재작성해
통과분만 고르는 구조가 아니다. 같은 배경의 다음 장면에서 첫 소개를 복구하는 작업은 별도다.
이번 수정에서는 검수 프롬프트·판정 기준이나 추가 재작성 경로를 바꾸지 않았다.

## 남겨둔 후속 문제

- 실제 작성·검수에서 어떤 주장과 근거의 연결이 어긋나는지 좁힐 것. 특히 공간 2의 경로 표현이 통과한 이유를 요청·판정 단위로 확인한다. 이번에 새 검수 설계를 추가하지 않았다.
- `current_motion()`은 적용 시각을 포함하는 근거라도 시간 구간 조합이 다르면 모두 비울 수 있다. 속도·모양의 유효 구간이 다른 입력을 상류에서 실제로 만드는지 먼저 확인해야 한다. 아직 재현된 제품 오류로 단정하지 않는다.
- `SemanticReview.passes`는 일기 가독성 실패나 issue 하나로 후보 전체를 거절한다. 맞는 문장의 과잉 거절 사례가 이 경로에서 발생하는지 확인할 것.
- `docs/README.md`에 기준 브랜치부터 있던 병합 충돌 표식이 남아 있다. 이번 수정과 별개이며 임의로 다른 작업자의 문서 선택을 정리하지 않았다.

- [checksums.json](checksums.json): 보관 파일 및 압축 전 원문의 SHA-256.

gzip은 용량만 줄이며 JSON 원문은 바꾸지 않았다. Python 표준 `gzip.decompress`로 해제할 수 있다.
재현 시 `prepared.json.gz`의 내용을 `generate_prepared_relational_diary`에 전달하고 manifest의
모델·검수·호출 간격·제한을 사용한다. API 응답과 의미 검수 결과의 동일 재현은 보장되지 않는다.
실험 입력을 새 자료로 다시 수집하거나 채택된 후보만 골라 비교하지 않는다.
