## 0. 한 장 요약

- **콘솔은 코드 하나, 배포 두 곳이다.** 로컬 `daengs.~/console`(개발 DB) · GCP `daengapp.~/console`(운영 DB).
  "GCP 용 콘솔" 을 따로 만들지 않는다 — **운영 값이 있는 쪽이 운영 콘솔**이고, 로컬 콘솔은 그 화면을 배포 전에
  확인하는 자리다. 로컬 콘솔의 중요성이 덜해 보이는 이유가 그것이고, 그건 문제가 아니라 배치다 (§2 배포).
- **지금 콘솔은 관리자 콘솔이 아니라 개발자 점검 도구다.** 열린 메뉴 2(기능 점검 · 크롤)는 전부 "우리 기능을 우리가
  두들겨 본다" 이고, **사용자가 남긴 것**(신고 · 회원 · 대화)과 **시스템이 남긴 것**(지표 · 상태)을 보는 화면은
  하나도 없다. 준비 중 3 은 카드 문구만 있다 (§2).
- **AI 답변 신고는 앱에 이미 있는데 콘솔이 모른다.** 답변을 길게 누르면 **메일 앱**이 열려 `sajoyodaengs@gmail.com`
  로 간다 — 사용자 ID · request_id 없이 답변 원문만. 서버로 오게 하려면 "어느 답변인지" 가리킬 행이 필요하고,
  그것이 #131(대화 저장)의 `chat_turns` 다 (§3).
- **첫 카드는 신고가 아니라 그 앞의 것들이다.** 관리자가 회원 대화를 보는 범위(새 `D-`) · 감사 로그(누가 봤나) ·
  관리자 계정을 ADMIN 하나가 아니라 역할별로 발급하는 것. 신고 화면은 이 셋 위에 선다 (§5).
- **09-21 전에도 DB 를 바꾼다** (사람 결정, §7). 대가는 카드마다 두 DB(로컬 · GCP) 손 적용이다
  (`docs/deploy/roadmap.md` §2-5).

## 1. 왜 필요한가

"있으면 좋다" 가 아니라 **지금 그 일을 어떻게 하고 있나** 로 잰다. 콘솔이 없어서 안 되는 일은 없다 — 전부
psql · Gmail · SSH 로 된다. 콘솔이 바꾸는 것은 **그 일을 할 수 있는 사람의 수**와 **흔적이 남는지**다.

| 일 | 지금 어떻게 하나 | 콘솔이 있으면 | 트랙 |
| --- | --- | --- | --- |
| 신고 메일이 왔다 | Gmail 을 연다. 답변 원문은 있는데 누가 · 언제 · 어떤 질문에 · 무엇을 근거로 낸 답인지 없다. 재현하려면 점검 탭에 같은 질문을 넣어 본다 | 신고 목록 → 그 turn 의 질문 · 답변 · `public_response`(근거 · status) · 처리 상태. 같은 답변이 몇 번 신고됐는지 | A1 |

## 3. 신고 경로 — 지금과 목표

```
지금 (DAENGS_APP ui/chat/ReportAnswer.kt)
  답변 길게 누르기 → 메일 앱 → sajoyodaengs@gmail.com
  본문 = 신고 이유 + 답변 원문.  사용자 ID · 토큰 · request_id · 질문 없음
  ("서버 대화 저장은 v0.0.0 범위가 아니므로" — 앱 주석)

목표 (2026-09-03 사람 결정 — 둘 다 유지, §7)
  답변 길게 누르기 → POST /app/reports {turn_id, reason}      ← 앱 v0.0.1 (#131 의 chat_turns 가 있을 때)
                  → answer_reports → GET /admin/reports → /console/reports
  메일 경로는 남긴다 — 구버전 앱 · 저장 안 된 대화(v0.0.0 무상태 경로)용.
  콘솔은 API 로 온 것만 본다. 메일 건은 콘솔에 옮겨 적지 않는다 (§6).
```

**신고 행이 가리키는 것** — `chat_turns.id`. 거기에 `user_content` · `assistant_content` · `public_response`
(status · citations · 능력) · `request_id` · `agent_categories` 가 있다 (#131 `db/init/07_chats.sql`). 콘솔 상세
화면은 이 행을 그대로 보여 주면 된다 — 신고 테이블에 답변을 복사하지 않는다 (§6).

**넘어야 할 것 — 권한.** D-048 은 "사용자가 다시 여는 제품 데이터" 로서의 저장을 허용했지 **관리자가 회원 대화를
본다** 를 정하지 않았다. 신고된 turn 만 보는가 · 그 세션 전체를 보는가 · 누가(어느 `Perm`) 보는가 · 사용자에게
무엇을 고지하는가 — 새 `D-` 가 필요하고 A0 이 그것을 낸다 (§7). 본 사실은 A4 감사 로그에 남긴다.

**앱 쪽 동반** — `ReportAnswer.kt` 가 turn id 를 알아야 한다. 앱 카드는 DAENGS_APP 이 연다. 이 문서는 API 계약
(요청 필드 · 응답)만 A1 에 적는다.


- **A4(감사 로그)가 A 트랙 맨 앞인 이유** — A2 의 복호화 · A3 의 발급 · A1 의 신고 처리가 전부 "누가 했나" 를
  남겨야 하는 일이다. 뒤에 넣으면 세 카드를 다시 연다.

  가리기가 검증된다. 지금은 전원 ADMIN 이라 권한 코드가 실행되지 않는다.
