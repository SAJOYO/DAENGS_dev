# 응답 에이전트와 이 레포의 경계 — 조언은 저쪽, 실행은 이쪽

지금까지의 논의는 "LLM = 발화를 툴 호출로 번역하는 한 겹"(결정 #18)까지만 다뤘다.
실제 제품의 LLM은 그보다 위에 있고, 판단 근거도 모델 지식이 아니라 **생활·의료·훈련
RAG**다. 그 층은 이 레포 관할이 아니지만, 그 층의 모양이 **우리 API 계약을 규정한다.**
이 문서는 그 경계만 적는다.

## 응답 구조

```
발화 ("애가 밤에 토했어" / "주말에 애랑 갈 데 없나")
  │
  에이전트: 상황 분석 (RAG 사용 여부는 상황이 정한다 — 의료면 의료 RAG, 가벼운 외출이면 없이도)
  │
  ├─ ① 조언: 상황 분석과 대처. 단편 명령("병원 가라")이 아니라 설명
  ├─ ② 등급 판정: 응급도는 그 한 사례
  └─ ③ 제안 모드 선택: 병원 · 약국 · 카페 · 산책로 · 제안 없음
         │  모드에 맞는 검색 조건을 세팅 → 우리 엔진이 결정론으로 실행 → 카드가 조언에 딸려 나온다
```

**제안은 조언의 부속이다.** 검색 카드가 독립 응답이 아니라 상황 분석에 딸려 나온다.
병원은 특수 케이스가 아니라 시설 일반의 공통 구조 중 한 모드다.

## 무엇을 LLM 에 맡기고 무엇을 안 맡기나

| | 주체 | 이유 |
|---|---|---|
| 상황 분석·조언 | 에이전트 (RAG) | 근거가 저쪽에 있다 |
| 등급 판정 (응급도 등) | 에이전트 (RAG) | 우리는 임상 판단 못 한다. 인허가 데이터엔 진료 능력이 없다 |
| 제안 모드·검색 조건 선택 | 에이전트 | 상황을 읽어야 나온다. 규칙표로 다 못 덮는다 |
| **검색 실행** | **이 레포 (결정론)** | 사람이 UI 로 똑같이 만들 수 있어야 한다 |

불변식: **LLM 이 꺼지면 편의성은 떨어져도 사용 가능한 기능 집합은 줄지 않는다.**
자연어 진입은 사라지지만 모든 필터·정렬·조건 검색은 그대로 된다.

이 경계가 08-23 대화의 "긴급도 판단을 우리가 어떻게 하냐"를 해소한다 — 판단 근거가
있는 쪽이 판단하고, 데이터가 있는 쪽이 실행한다. resolver 안의 상황 정책
(urgent → open_now 강제, 소요시간순)은 그래서 우리 코드에서 나가야 한다 (아래).

## 그래서 우리 쪽 숙제

1. **검색 어휘의 완전성·기계 가독성** — kind·반경·require/prefer/exclude·정렬을 전부
   edits 계약으로 노출한다. 모드가 무엇을 고르든 사람이 UI 에서 똑같이 만들 수 있어야 한다
2. **문장 생산 중단** — 응답의 `reply` 는 에이전트 몫이다. 우리는 구조화 데이터
   (results · changes · resolution trace · 한계 계수 · suggested edits)만 낸다.
   `reply` 는 `/dev` 콘솔용으로 강등 (결정 #9 갱신)
3. **한계는 문장이 아니라 데이터로** — `hours_source{name, as_of}` · 표방 태그 · 미상 계수.
   합성 과정에서 문장이 재작성돼도 살아남아야 한다. 이게 없으면 조언("24시간 병원으로")과
   우리 결과가 합성될 때 **어느 쪽도 하지 않은 주장**("이 병원들이 그 24시간 병원")이 생긴다
4. **resolver 3분할** — 기계적 해석(시각·kind·기본 반경)은 남기고, 상황 정책은
   suggester 로 빼서 일반 edits 로 출력하고, 의미 규칙은 `geo/ranking.preference_tags`
   (#24 에서 완료)

## 팀 경계에 물어야 할 것

1. 합성 방식: 라우터 fan-out 자유 합성 / **슬롯 합성**(조언 블록 + 행동 블록, LLM 은
   접속 문장만) / 툴 쓰는 단일 에이전트 — 우리가 미는 것은 슬롯 합성이다.
   출처·한계 표기가 합성 후에도 보존되는 유일한 형태이기 때문
2. 두 lane 충돌 시: RAG 는 "병원 가라"인데 검색 결과 0곳, 또는 반대
3. `reply` 소유권 이관 (우리 제안: 이관)
4. 긴급 시 제안 자동 적용 vs 승인 요구 — 마찰이 위험이 되는 순간이 있다. undo 는 이미
   턴 단위로 있으므로 자동 적용 + 즉시 되돌리기도 성립
5. 산책도 동일: `scene/judgment` 출력(passed/lingered)을 서술로 바꾸는 것도 같은 에이전트인가
