# 산책 공간 재료 정규화

정규화의 실행 정본은 DEV의 `daengs_walk.diary.space`다. GEO의 케이스 사전과
판정 의미를 이식했다. APP은 서버 결과를 수신·저장·표시한다.
공간은 API, 동선 패턴은 GPS, 행동은 선택적 행동핀 앵커다. 행동핀 없는 장면도 유지한다.
GPS 재료의 실제 연결은 [동선 패턴 정규화](route-patterns.md)를 따른다.

정규화 이후의 [공간 적용 정책·스냅샷 재생](space-policy.md)은 별도 실험이다.
재료별 범위와 기존 용량 손실을 확인하며, 이 문서의 실제 발행 정책을 자동 전환하지 않는다.

## 실행 경로

```text
상권: 완전한 범위를 덮는 카탈로그 / 공공 API 응답
공원: 미리 갱신한 전국 카탈로그
피복: WMS GetFeatureInfo
  → 유한한 사전으로 정규화 (material / scope / support)
  → 선택된 보드·core·anchor·조회 좌표에 결합
  → 기존 제외·충돌·용량 정책 → 스탬프
  → 의미와 적용 관계를 writer에 전달 → 기존 일기 발행·JSONB 저장
  → APP의 기존 일기 응답·Room 저장·상세 재진입
```

미리보기와 발행은 `prepare_board_slots`를 공유한다. 새 역할을 임의로 추가하지 않고
상권은 `scene_area_context`, 공원은 `scene_registered_point_distance`, 피복은
`scene_geometry_distance`에 연결했다. 미지원 역할은 조용히 누락하지 않고 제외 사유를 남긴다.

정규화 수집을 사용하는 장면에서는 이전 공원·상권 nearby 요약을 이중 입력하지 않는다.
별도 하천 API도 이 경로의 재료에서 제외한다. 기존 nearby 반환 형식과 다른 소비자는 유지한다.
피복의 하천·호소 분류는 토지피복 사전의 일부이므로 그대로다.

## 보존한 의미와 수치

- 68개 케이스: 피복 세분류 41개, 공원 종류 11개와 미상 종류의 일반 공원,
  상권 업종 구성 12개와 분포 3개. 사전 해시:
  `b15c4f74fe05843b5e56a1954a95b4374ebfba0274261e3eb6b3f842eb37a08c`.
- 상권은 업소 5개 이하를 적음, 구성 판정 최소 10개, 우세 비율 0.4·차이 0.15,
  등록 좌표 RMS/조회 반경 0.25를 초기 기준으로 사용한다. 제품에서 보정한 확정 임계값은 아니다.
- 업종 구성과 공간 분포는 한 후보의 서로 다른 `case_ids`로 함께 보존한다.
  같은 건물의 여러 업소는 구성에서 각각 세고, 공간 분포에서는 동일 등록 좌표를 중복 계산하지 않는다.
- 조회 반경은 명시적 입력이다. 실제 수집 기본값은 1km지만,
  이전 A/B의 500m 입력 재생에는 500m를 그대로 사용한다.
- 기존 슬롯 정책의 공간 3개·등록점 거리 250m 등은 변경하지 않았다.
  정규화 후보가 전부 작성 입력에 들어간다는 결정은 아니다. 용량 정책은 별도 실험 대상이다.

피복은 다른 자료의 상위 판정자가 아니다. 피복 실패와 무관하게 공원·상권은 각자 남는다.
‘피복보다 추가 서술 가치가 작은가’를 퇴거 조건으로 도입하지 않았다.

## 원자료 보존 경계

`walk_space_catalog_input.retain_page`가 아래 필드를 기존 요약·행 제거 **이전**에 보존한다.
원래 페이지 번호·총건수·공급자 헤더도 유지하며, 실패·중복·충돌 행을 성공 자료로 꾸미지 않는다.
`normalization_pages`와 별도 해시를 기존 카탈로그에 추가한다. 예전 카탈로그의 요약에서
누락 필드를 복원하거나 완전한 응답을 합성하지 않는다.

| 자료 | 정규화에 필요한 원래 필드 |
| --- | --- |
| 상권 | `bizesId`, `lat`, `lon`, `indsLclsCd`, `indsMclsCd`; 헤더의 `stdrYm` |
| 공원 | `manageNo`, `parkNm`, `parkSe`, `latitude`, `longitude`, `parkAr`, `referenceDate` |
| 피복 | feature ID, `l3_code`, 선택적 `l2_code`·`img_date`, CRS, Polygon/MultiPolygon |

공원 날짜만 다른 동일 장소는 날짜 이력으로 합친다. 이름·종류·위치·면적 충돌은 해당 ID를
제외하고 다른 공원은 유지한다. 상권 분포는 완전한 응답과 유효한 업종 구성이 필요하다.
카탈로그를 읽을 때는 유효기간·해시와 **분류할 원 전체가 수집 범위 안인지**를 확인한다.
기존 1km 격자의 1200m 수집본이 현재 좌표의 1km 원 전체를 덮는다고 가정하지 않는다.

## 작성 입력과 내부 재료

```json
{
  "material": {"업종구성": "음식점·카페 중심", "분포": "등록 상가가 모인 구간"},
  "relation": {
    "kind": "registered_distribution_in_query_circle",
    "radius_m": 500,
    "nearest_registered_point_m": 349.283,
    "centroid_distance_m": 406.752
  },
  "temporal_basis": "lookup_snapshot"
}
```

이 예시의 ‘모임’은 조회 범위 안 등록점의 분포다. 현재 지점이 그 상가 사이에 있다는 뜻이 아니다.
349m를 새 공통 퇴거 임계값으로 삼지 않는다. 공원은 등록점 거리이며 경계·내부 관계가 아니다.
피복은 반환 형상이 조회점을 포함하는지 검사한 결과이며 동선 전체의 배경이 아니다.

writer는 정규화된 `material`과 `relation`을 받는다. 업소 ID 목록·집계 분모·분류 임계값·
전체 경계 형상은 내부 `scope`·`support`에 남는다. 다른 장면의 순서·시각과 대표 시설 강제는
이전 비교 writer에서 제거했다. 후속 [장면·선택적 행동 서술](scene-writing.md)은
일반 장면의 완결된 본문을 받으며 특별한 순간 원문은 보존한다.

## 트랜잭션·보존

발행은 소유자 입력을 읽은 뒤 커밋하고 조회한다. 조회가 끝나면 다시 원본을 읽어 잠금을 잡고,
동일 보드·core·anchor인지 검사한 뒤 예약한다. 쓰기 도중 변경도 기존 세대 검사로 차단한다.
조회 중 원본이 바뀌었다면 수집본을 다른 장면에 붙이거나 이전 원본으로 발행하지 않는다.

외부 수집은 최대 12개 장면·동시 4개, 수집 대기 4초다. 완료한 공급자 결과는 유지하고 나머지는
고정 실패 사유로 남긴다. 발행 전체의 남은 예산도 지킨다. 모든 외부 API의 정상 완료를
5초 이내에 보장한다는 뜻은 아니다. 공원 전국 수집은 요청 중 실행하지 않는다.

발행 JSONB에 결합된 수집본과 해시를 함께 저장한다. 조회·재사용은 그 수집본으로 재현하며
외부 API를 다시 부르지 않는다. 공개 응답에는 내부 카탈로그·후보 전체를 추가하지 않는다.
이전 저장본에는 새 필드를 채워 넣지 않으며 기존 본문을 보존한다. DB 스키마 변경은 없다.

## 사용·검증

실행 명령은 [코드 옆 안내](../../backend/src/daengs_walk/SPACE_NORMALIZATION.md)에 있다.
운영에서는 카탈로그를 다시 갱신해 `normalization_pages`를 확보한 뒤
`DAENGS_WALK_DIARY_SPACE_ENABLED=true`로 실제 발행 경로를 활성화한다.
미리보기는 `collect_backgrounds=true`로 동일 수집기를 사용한다.
APP #364는 이 미리보기 필드가 있는 DEV #474 이후에 적용한다. 기존 발행 응답 형식은 같다.

2026-09-13 로컬 검증:

- 저장된 실제 A(37.487, 127.052)·B(37.5445, 127.0374) 응답을 재생했다.
  GEO 결과와 **전체 JSON 동등**: 분류·범위·거리·출처·완전성·제외 사유까지 일치했다.
  정규화만 A 0.306초, B 0.271초. API/파일 읽기/프로세스 시작 시간은 제외한다.
- B는 피복 응답이 없었던 원래 실험 그대로 비교했다. 공원 전체 목록의 충돌 진단도 보존했다.
- 합성 입력으로 수집 실패 독립성, 제한 시간, 핀 없는 장면, 같은 수집본의 미리보기/발행
  슬롯 동등성, 원본 변경 차단, 실제 HTTP 발행 어댑터와 저장·재조회를 검사한다.
- `backend/evals/walk-diary/space-board-v1.json`은 HTTP 경로와 가짜 writer로 만든 합성 응답이다.
  APP의 동일 바이트 fixture로 Room 수신·DB 종료·재열기·일기 읽기를 검증한다.
  실제 Gemini 문장 품질이나 운영 서버에 배포했다는 근거로 사용하지 않는다.
