# 명시적 찜 명령 출력 평가 — 2026-09-11

[실행 계약](bookmark-commands.md)의 1단계를 검증했다. 실제 Gemini 해석을 운영 정책에
통과시키되 검색 결과는 합성 KCISA 장소 A/B/C를 썼다. 회원 API 쓰기와 운영 DB는
호출하지 않았다. 앱 실행은 별도 API 대역을 사용하는 연결 테스트로 검증했다.

## 실제 모델 관측

모델은 `gemini-3.1-flash-lite`. 입력 12개에는 명시적 저장·해제, 여기/번호/상호명,
칭찬, 이미 아는 곳, 정보 이의, 부정과 다음 탐색, 복합 요청, 없는 대상, 인용을 넣었다.
각 실행 폴더에는 입력 사본, 설정·소스 SHA-256, 원문 출력·정책 결과가 있다.

| 실행 | 범위 | 통과 | 실패 | 미완료 |
|---|---|---:|---:|---:|
| [첫 실행](../../backend/evals/place_conversation/bookmark-runs/20260911T081358Z/) | 12문장 × 2회 | 17 | 3 | 4 |
| [수정 후 재확인](../../backend/evals/place_conversation/bookmark-runs/20260911T081932Z/) | B03·B05 각 1회 | 2 | 0 | 0 |

첫 실행의 실패 3건은 B03 “여기 남겨둬” 2회와 B05 “'평가 카페 A'만 찜해줘” 1회다.
모델은 저장 의도와 대상을 맞췄지만, 동작 인용으로 문장 전체를 반환했을 때 서버가
동사 구절만 허용하여 명확화로 내렸다. 원문 포함 여부와 요청 전체의 단일 긍정 명령
검증을 유지하면서 문장 전체 인용도 허용했고, 두 문장을 다시 호출해 통과했다.

미완료 4건은 모두 HTTP 429이며 B04·B05·B07·B09의 두 번째 반복이다.
통과율 계산에서 성공으로 취급하지 않았고, 수정 후 전체 24건을 재검증한 것도 아니다.
완료된 관측에서는 원하지 않은 찜·제외 변경이 없었다. 작은 합성 표본이므로 임의의
말투나 운영 분포에 대한 정확도 보장은 아니다.

## 회귀 검증

- 서버 기존 정책·제외 근거·대화 서비스/API 58개 통과. 추가 찜 계약·API 20개는
  마지막 수정 후 모두 통과했다. 총 78개 고유 테스트이며 전체 스위트는 실행하지 않았다.
- 초기 신규 테스트 실패는 합성 장소의 key와 match/classification 출처가 달랐던
  fixture 오류였다. 출처를 일치시킨 뒤 인용 상호명의 조사 처리 실패를 별도로 고쳤다.
- 앱은 완료 대기, 응답 유실 후 조회, 불명 결과, 같은 장소의 새 조작, 다른 장소 조작,
  요청 재실행, 취소·계정 생애, 검색 조건 변경 중 응답, 피드백과 새 선택 보존을 검증한다.
  앱 PR의 대상 테스트와 debug 빌드는 실제 기기/회원의 종단 검증을 대신하지 않는다.
- 서버 `uv run check`와 변경 Python 파일 Ruff 검사 통과. DB·환경 변수 변경 없음.
