# 시설 응답 표시 정책

시설은 지도·조건·카드를 조작하고, 대화는 실제로 한 행동을 짧게 알린다. 응답을 다시 쓰는
LLM 호출은 추가하지 않는다. 연결 계약은 [assistant-conversation.md](assistant-conversation.md)를 따른다.
시설 밖 입력의 강아지 문구·실행 제한·이력 및 확인 대기 보존은 [시설 범위 정책](scope-guardrails.md)을 따른다.

## 표시 경계

| 경로 | 판단 근거와 표시 책임 |
| --- | --- |
| 시설 성공·실패·확인 | Place `render.py`가 커밋된 receipt로 문장을 만들고 `presentation.py`가 내부 용어·길이·문장 수를 검사한다. |
| 공통 위치 확인·실행 오류 | `orchestration/facility_presentation.py`가 시설 계약 요청의 사용자 문구를 바꾼 뒤 기존 집계를 거친다. |
| APP 복구·찜 완료·수신 문구 | `FacilityResponsePolicy`가 복구 결과와 실제 찜 완료 상태를 보고 표시한다. 일반 시설 대화와 공통 채팅이 같은 정책을 쓴다. |

위치가 없다고 위도·경도 입력을 요구하지 않는다. 현재 위치 확인을 안내하며 구조화된
`clarify.missing`은 유지한다. 오류 종류·request/session ID·revision도 기계 계약에 남지만
대화 문구로 쓰지 않는다. 다른 기능의 답변과 의료 안내는 시설 길이 제한으로 축약하지 않는다.

## 내용·말투·길이

`invalid_plan`은 모델 제안의 검증·해석 실패다. 이 경우 사용자에게 조건을 더 구체적으로 쓰라고 요구하지 않고 **“앗, 요청을 처리하지 못했어요. 다시 시도해 주세요 🐾”**로 안내한다. 서버는 새 receipt의 질문과 렌더링에 이 문구를 쓰고, APP도 같은 코드에서는 과거의 잘못된 질문·내부 문구·빈 응답을 실패 안내로 바꾼다. 실제 실행 실패의 구체적인 결과가 있으면 그 결과를 우선한다.

`clarification_required` 등 실제 정보 부족 질문과 `facility_out_of_scope`의 강아지 안내는 별도 경로다. 기존 `invalid_plan`의 필터·카드·선택·이력·유효한 확인 대기 보존 계약을 유지한다. 표시 개선은 검색이나 찜을 재실행하지 않으며 자동 재시도를 약속하지 않는다.

2026-09-17: 검색 의미를 고정 단어와 원문 인용으로 다시 판정하는 경로를 제거했다. 기존 OR 조건의 업종 변경은 서버가 계산한다. 잘못된 도구 출력에는 **실행 전 인자 수정 1회**만 허용하고, 실패 안내를 성공으로 바꾸지는 않는다. 도구 인자·검증 로그는 채팅에 표시하지 않는다. 상세는 [해석·실행 경계](scope-guardrails.md#해석과-실행)와 [OR 변경 규칙](scope-guardrails.md#업종-변경과-or-조건)을 따른다.

- 실제 실패를 성공으로 바꾸지 않는다. 찜 명령 준비는 저장 완료가 아니다. APP은 실제 결과를
  기다리며 확인하지 못한 경우 저장했다고 말하지 않는다.
- 세션·revision·receipt·스냅샷·원천 정보·토큰·내부 키·UUID·JSON 등의 표현을 검사한다.
  걸린 문구는 부분 삭제하지 않고 실제 상태에 맞는 짧은 문구로 대체한다. 외부 시설명이
  내부 코드처럼 보이면 이름을 숨기고 선택 사실을 알린다.
- 기본 한 문장, 실패·확인·정보 한계 설명은 두 문장까지, 일반 문구는 160자까지다.
  성공은 “골라뒀어요!”처럼 가볍게, 오류와 확인은 차분하게 말한다. 이모지를 강제하지 않는다.
- 확인 질문은 동의할 조건을 숨기면 안 되므로 최대 300자까지 허용한다. 조건 전체를 예산
  안에서 설명할 수 없거나 내부 표현이 포함되면 제안을 저장하지 않고 조건을 나눠 말해 달라고
  요청한다. 이전의 부적절한 제안도 “응”으로 실행할 수 없게 폐기한다.
- “등록된 정보에는 주차할 수 있다고 나와요.”처럼 정보의 한계를 유지한다. 짧게 만들려고
  현장 확인을 완료했다고 바꾸지 않는다.

표현 검사는 정해진 내부 용어와 형식에 대한 방어다. 임의의 새 내부 용어를 모두 알아내는
의미 판별 모델이 아니다. 새 상태·오류·문구는 템플릿과 회귀 사례를 함께 추가한다.

## 만료 복구와 로그인

기존 시설 요청은 `FacilitySessionPayload`로 세션 참조를 전달한다. 최초 검색의 `PlacePayload`는
기기 위치를 계속 요구한다. 만료된 검색은 GPS 없이도 owner 검증을 거쳐 `facility_expired`를
반환하므로 APP이 보관한 조건으로 복구한다. Walk를 함께 요청하면 실제 GPS 요구는 유지한다.
모델에는 시설 화면이 있다는 힌트만 보내며 세션 ID·카드·좌표를 보내지 않는다.

APP은 `SessionProvider.accountScope`의 owner·generation으로 로그인 생애를 구분한다.
정상 토큰 회전은 진행 중인 응답을 무효화하지 않는다. 같은 회원의 재로그인과 로그아웃은
오래된 응답을 차단한다. 공통 요청과 recovery에는 같은 로그인 안에서 갱신한 인증을 쓴다.
