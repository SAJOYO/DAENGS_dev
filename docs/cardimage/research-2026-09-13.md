# 조사 — 사용자 강아지를 참조 카드에 넣는 방법 (2026-09-13)

한 세션 동안 검색해 모은 것. 가격·모델 이름은 **2026-09-13 기준**이고 빨리 낡는다.
결론은 README 에 있고, 여기는 왜 그렇게 봤는지의 근거다.

## 1. 과제의 성격

"참조 사진의 강아지를 다른 그림에 넣되 그 그림의 구도·배경은 유지" — 2026 기준으로
**참조 이미지 편집(reference-based / instruction-based editing)** 한 갈래로 수렴했다.
이미지 두 장(장면 + 강아지 사진)과 지시문을 넣으면 편집된 이미지가 나온다. 사람 얼굴용
기술(InstantID 류)이 아니라 일반 피사체를 다루는 모델이어야 한다.

## 2. 방법 네 갈래

| | 방법 | 장점 | 단점 |
| --- | --- | --- | --- |
| A | **호스팅 API 에 참조 이미지 편집** | GPU·인프라 없음, 품질 상위 | 모델 내부를 못 만짐, 장당 과금 |
| B | **오픈 가중치를 직접 돌림** (Qwen-Image-Edit 등) | 마스크·LoRA·양자화 등 세부 조정, 포트폴리오에 보여 줄 층이 생김 | GPU 를 빌려야 함, 콜드스타트, 운영 |
| C | **강아지마다 LoRA 학습** | 닮음 최고 | 사진 5~20장 필요, 학습 대기, 사용자별 가중치 보관, 구도 교체는 결국 A/B 가 또 필요 → 업그레이드 경로 |
| D | **마스크 인페인트 혼합** | 강아지 영역만 다시 그려 틀·문구 픽셀 보존 | 마스크를 카드마다 한 번 만들어야 함 |

우리 카드는 문구가 PNG 에 구워져 있어서, D 의 취지를 더 싸게 얻는 방식으로 **"틀 안쪽 그림
영역만 생성하고 머리띠·아래판은 원본으로 덮는" art 모드**를 실험 기본으로 잡았다
(`cardimage_try.py`). 아바타 원은 AI 없이 사진에서 오려 붙인다.

### 해당 없는 것

- **LTX-2 / 2.5** (Lightricks): 영상 모델. 사진 한 장 → 소리 붙은 영상. 완성 카드를 움직이는 홀로그램 영상으로 만드는 후속에나 해당.
- **Krea 2** 본체: 스타일 참조(무드보드) 특화 텍스트→이미지. 편집판은 "만드는 중, 기한 미정". 정체성(이 강아지)을 옮기는 통로가 없다.
- Krea 2 캐릭터 LoRA 학습: 127~500장·96GB GPU·4.5시간 또는 Krea 구독 베타. 사용자마다 사진 한 장 넣는 흐름에 안 맞음 (C 갈래).

## 4. Qwen-Image-Edit 을 돌리는 방식 — 두 축

실행 코드(①)와 GPU 자리(②)가 따로다.

| | ① 실행 코드 | ② GPU | 우리가 관리하는 것 |
| --- | --- | --- | --- |
| fal (호스팅 API) | fal | fal | 없음. HTTP 호출만 — Nano Banana 호출과 같은 부류 |
| ComfyUI | 노드 워크플로 (러너) | **따로 빌림** | 워크플로 JSON · 모델 파일 |
| diffusers (Python) | 우리 코드 | **따로 빌림** | 코드 · 모델 파일 |
| GCP Cloud Run GPU / RunPod / Modal | 없음 — 자리만 | 여기 | 컨테이너 · 켜고 끄기 |

- 세부 조정(마스크·참조 강도·LoRA·양자화)은 **ComfyUI 또는 diffusers** 에서만. fal 은 엔드포인트가 연 인자만.
- 조정 폭은 diffusers > ComfyUI. 시행착오 속도는 ComfyUI 가 빠름. **ComfyUI 는 모델이 아니라 러너**라 "ComfyUI 로 서빙" 은 늘 뒤에 ② 가 붙는다.
- 포트폴리오 관점: 오픈 모델을 코드로 직접 돌리는 경로가 보여 줄 층이 가장 많다 (모델 로드·양자화·마스크·LoRA·선택 근거). API 단독은 얇고, ComfyUI 는 산출물이 JSON 이라 코드 리뷰 대상이 안 된다. 권고 구성은 **오픈 경로 + 호스팅 경로를 같은 어댑터 뒤에 두고, 닮음 평가 하네스로 숫자로 고르는 것** — 이 저장소의 `daengs_evals` 문법과 같다.

### 월별

| 월 생성량 | Nano Banana 2 | fal Qwen | 서버리스 GPU | 상시 포드 |
| --- | --- | --- | --- | --- |
| 300 | ~$20 | ~$9 | ~$10~20 | $250~ |
| 3,000 | ~$200 | ~$90 | ~$60~100 | $250~ |
| 30,000 | ~$2,000 | ~$900 | ~$600 | $250~360 |

재시도 1회면 API 쪽 ×1.5. 12개월 카드로 넓히면 유저당 ×12. **손익 분기는 월 5천 장 근처.**
서버리스 GPU 의 진짜 비용은 돈보다 콜드스타트(사용자 대기)와 운영 부담이다.

### 결제

- **Gemini API**: 선불(Prepay) 기본, 최소 $5 · 최대 $5,000. 후불은 2026-03-23 부터. Nano Banana 2 는 **무료 구간 없음.** 선불 잔액은 **Cloud 결제 계정** 단위, 지출 상한·사용량은 **프로젝트** 단위, 키는 프로젝트의 결제 상태를 물려받을 뿐 → "충전 하나, 관리 따로" 는 **프로젝트를 둘로** 나눠야 한다 (키만 둘이면 합산). 그래서 카드 생성용 프로젝트를 따로 팠다.
- **fal**: 선불 크레딧, 월 최소 없음, 성공 출력만 과금, 큐 대기·서버 오류 무료. 구매 크레딧 365일 만료. 가입 크레딧 있음(금액 미공개). **최소 충전 금액은 문서에 없고 결제 화면에서만 보인다.**

## 6. 앱이 실제로 보내는 사진 크기 (DAENGS_APP)

| 경로 | 크기 | 형식 | backend 상한 |
| --- | --- | --- | --- |
| 강아지 프로필 사진 (`PetPhotoPicker` → `Photo.decodeUpright`) | 긴 변 **1600px** | JPEG q90 | 8 MiB (`services/pet.py`) |
| 피부 검사 사진 (`screening/Photo.kt`) | 긴 변 1600px, 썸네일 512 | JPEG q90 | 12 MiB |
| 도감 카드 얼굴 누끼 (`ui/dogcard/Cutout.kt`) | 긴 변 **900px** | PNG 알파 | 4 MiB, PNG 만 (`services/dogcard.py`) |
| 산책 사진 | 메타데이터만 동기화, 파일 업로드는 후속 | | |

기존 카드 캔버스는 1080×1440, 참조 카드는 994×1582. Gemini 는 큰 입력을 긴 변 약 3,072px 로
자동 축소해 받고, 입력 이미지 토큰은 장당 몇 백~천 수준이라 원본/1600 의 요금 차이는 없다.
차이는 전송 시간뿐 → **줄일지는 실험 1·2 로 정한다.**
